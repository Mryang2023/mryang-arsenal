### 关键设计决策（后续实现须遵守）

1. **功能聚类用调用闭包，不用命名相似** —— 命名是猜、闭包是事实；命名只能用来起名字并标 `inferredBy:"name"`。
2. **体检观察项必须数据化**（新建第 9 事实源 `arsenal-checkups/*.json` + Java 只写解释器），
   规则判据复用 69 条。两者性质不同，混在一起会让「加一条体检项」变成改代码。
3. **棒 3 里的聚类重构不可拖** —— `CodeScanner` 现在是 `TreeMap` 一把聚合，无法「只重算 3 个文件的贡献」，
   L2 增量依赖它，拖到最后 L2 就是个假的「快速」。
4. **剥离产物必须报告切断了什么** —— 外部依赖默认给两个选项（连带剥离/替换为桩），
   偷偷塞半个依赖模块 = 编译不过 = 前面白做。验收硬标准：`mvn -q compile` 真能过。
5. **快照三档目录**（默认 `arsenal-web/.data/autopsy/` / `arsenal.json#project.autopsyDir` /
   env `ARSENAL_AUTOPSY_DIR`），**不进 git**（沿用 profile-store 已立的规矩）。
6. **「修好了」必须能点开看依据** —— 「P0 少了 2 个」和「2 条规则没跑」在页面上长得一样（10-04 踩过）。
7. **未解析的边必须显式列出**（`unresolvedEdges`）—— 反射/接口注入会漏边，漏边 = 剥离产物编译不过。

## 夜跑棒 2 · 体检报告（2026-10-12 01:56→04:2x，三棒链）

**产出**：`POST /api/autopsy/inspect`（AutopsyController + AutopsyService + CheckupLoader + CheckupEvaluator）、

实测真报告：覆盖 42/69、未覆盖 27 条、P0 53 条（扫自家 arsenal-server）、观察项 2/6 触发。

**本棒沉淀的四条**：

1. **「报告里不存绝对路径」这类断言必须落到产物上判，不能只判源码**。
   原先只查 `scope.rootName()` 就绿了，而 `obs.source` 把服务器的绝对路径原样 put 进了报告。
   补了源码断言之后**又踩一次**：写成「不含 `checkups.file()`」的正则**没有锚**，
   会把 `Path.of(checkups.file()).getFileName()` 里的 `checkups.file()` 当命中 → 断言恒真。
   **无锚正则与「一直为绿」长得一模一样**，改判「钉住整串 `Path.of(...).getFileName()`」+ 端到端对真 JSON 再判一次才堵住。
2. **snippet 是原始源码行，脱敏要第二道**。体检专扫 `yml`/`properties`，配置里写着真密码的
   那一行完全可能成为某条违规的证据行；扫描层 `ScanGuard.redact` 管的是配置项取值、管不到整行源码。
   加 `safeSnippet()`（键名口径与 `isSensitive` 同源），实测 `password = "hunter2-REAL-SECRET"` → `password = ***`。
3. **截断信号必须从 collect 里传出来**。`truncated` 原先只看文件数，总字节上限撑爆时仍是 false ——
   报告会说「扫完了」而后半截根本没进引擎。改成 `Collected(files, capped)`，两条路径都算。
4. **观察项事实源改了要重启后端**（CheckupLoader 在构造期加载，同 scan_rules 的既有口径）。
   反着验②因此是「删规则 → 重启 → 观察项 2/6→1/5 → cp 还原 → 重启 → 2/6」，**Java 一行没重编译** —— 这条才是「判据是数据」的真凭据。

### 本次抓到的三个真缺陷

1. **`.gitignore` 的 `.data/autopsy/` 没生效**。中间带斜杠的 pattern 会被锚定到**仓库根**，
   挡不住 `arsenal-web/.data/autopsy/` —— `git status` 里真冒出 `?? arsenal-web/.data/`。
   **同一个坑本仓 .gitignore 自己在第 47 行就写过一次**（`**/.workbuddy/_*`），
   这次又写了一遍。改成 `**/.data/autopsy/` 才真忽略（git check-ignore 退出码 0）。
2. **同一份输入有两个 projectId**：Node 侧 sha256、浏览器侧 FNV-1a。
   后果不是命名不统一 —— 是**按 Node 侧 id 过滤、按浏览器侧 id 命名文件**，
   `listSnapshots({projectId})` **永远查不到任何东西**（实测 10-5/10-6 红：`listed=0`），
   而页面只会说"这个地址还没有任何快照"。修法：算法收进共享的
   `autopsy-snapshot-shape.mjs`（FNV-1a 64，BigInt，两个运行时都 import），两侧各转发。
   **又一次印证：一个概念两个实现 = 静默失效，不是不一致。**
3. **空跑会被当成"没变"**：0 文件的指纹是 `report:xxx|0|0`，长得跟正常指纹一样 →
   上次什么也没扫到，这次照样判"输入未变化，复用"。加了 `fingerprintTrust()`
   （0 文件 / 被截断 → 不可信 → 不复用也不归入），页面上历史条目也打"指纹不可信"标记。

### 本次沉淀（会进 MEMORY.md 的候选）

1. **"注释让源码文本判据失效"栽了第三次**：10-4 判"指纹不许 readFileSync"，
   而 `autopsy-fingerprint.mjs` 的**文件头注释里正写着**"逐文件 readFileSync 会把…变慢"
   → 恒红。判源码文本前必须 `stripComments`（棒 1 的 9-6 是第二次）。
2. **本沙箱 spawnSync 对任何外部进程都返回 EBUSY**（bash / git / node 实测皆然）。
   于是：整条 `verify:scan` legacy 段（bash 探针）、`verify:archify` 3 项、
   `verify:visual`（要起浏览器）**全部跑不了**。依赖外部进程的断言只能 `skip()`
   —— **绝不许兜成通过**，但要在 detail 里写明原因，别让人以为它绿了。
3. **git URL 里内嵌的凭据必须脱敏再存**：`https://u:<token>@github.com/o/r.git`
   是私有仓库的常见写法，而快照要落盘、要被下载。脱敏必须发生在**算 projectId 之前**，
   否则"带令牌"与"不带令牌"的同一仓库会算出两个 id —— 又是一对平行身份。
4. **反着验要做满 6 处**（本棒做了 6 组注入，全部命中）：L1 复用总命中→10-10 红、
   差集 fixed 清空→10-11 红、damaged 不记录→10-8 红、删 .gitignore 条目→10-2a 红、
   指纹闸门失效→10-15 红、凭据脱敏失效→10-16 红。**第一次注入 3 直接把层跑崩**
   （push null 进去 → sort 时 TypeError），换成"静默 continue"才得到干净的红色
