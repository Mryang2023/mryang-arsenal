### 提交时撞上多会话并发（重要处置）

清点发现 95 条目里**混着两条别的线**：装配台步骤级菜单拆细（12 文件，`/stack/step/<id>` +
`STACK_NAV`，注释日期也是 10-05）与图标位图补齐（icons.json / icons.py / 60+ png / IconGallery）。
其中 **`Shell.tsx` 一个文件里两条线的改动交织**（章程 2 行 + stack 23 行）。

处置（不越界、不破坏别人的活）：
1. `cp` 备份工作区全量版 → `git show HEAD:` 取仓库版 → 在仓库版上**只加章程那 2 行** → 提交；
2. 提交后把全量版拷回工作区，别人的 stack 改动**原样还在**（md5 校验过）。
   这样仓库 HEAD 编译通过、章程侧栏入口也进库，而对方的 diff 之后只剩 stack 部分。

> 教训：并发下提交**不能按目录 pathspec 打包**，也不能把别人的半成品一起吞进去。
> 「拆出自己那部分 → 提交 → 放回」比「等对方提交完」快，也不背它的绿。
