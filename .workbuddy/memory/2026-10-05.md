### 拍板落地形态

| # | 决定 | 落地 |
|---|---|---|
| ① | 本仓脚本，不发 npm 包 | `arsenal-server/scripts/charter-ci.mjs`，**一个文件两种模式**：export 跑在军火库（读规则池+章程）产出自包含 `.arsenal/ci/{config.json, 执行器副本}`；lint 在业务仓 CI 里**零 import**（只用 node 内置） |
| ② | diff 在导出阶段算进 config | `resolvePrFiles()` 拿不到 diff **直接报错退出**，不把空清单当「本次没改文件」；判定阶段不再碰 git |

### 跨实现一致性 —— 防「两份实现」的核心机制

执行器是 .mjs、引擎是 .ts，没 import 引擎（跨语言边界更脆），改成**行为比对**：
同一批 L0 规则 + 同一批样本（规则自带的 `bad`/`good` 示例拼成 4 个文件），
`engine.ts` 的 `lint()` 与执行器的 `lintFiles()` 判出的 **(ruleId, file, line) 三元组必须逐条相同**。
另配一条「样本确实触发了命中」—— 否则一致性断言可能是恒真的。

**反着验两次都真红**：
- 去掉例外的 pathGlob 条件 → 恰好 1 条红；
- 把 `**/` 改成不允许零层目录 → 3 条红（含跨实现那条 + glob 逐例那条）。
