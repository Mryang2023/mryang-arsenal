# 提示词模板与状态文件

编排时按这些模板生成每棒 prompt。**每棒 prompt 必须自包含** ——
夜间 agent 看不到编排时的对话，也不会去翻技能目录。

---

## 一、`<N>-done.json` schema

这是棒与棒之间、棒与终检之间唯一的交接凭证。**字段不许省略**，尤其 `自检` 与 `review` 两段。

```json
{
  "棒次": 1,
  "任务": "任务短名",
  "方案": "plan-1-xxx.md",
  "状态": "完成 | 部分完成 | 未执行 | 失败",
  "开工": "2026-09-21T23:20:00+08:00",
  "收工": "2026-09-22T01:08:00+08:00",
  "模型": "实际运行的模型名",
  "时间预算": { "单棒": 175, "开发": 105, "自检": 35, "review": 35 },

  "开发": {
    "砍定范围": "开局砍成什么样（收工时对照它交账）",
    "做完的": ["具体到文件 / 阶段 / 断言编号"],
    "未做完的": ["具体到「哪个阶段 / 哪个文件 / 哪条断言」"],
    "降级处理的": ["前置依赖缺失时降级了什么、为什么"]
  },

  "自检": {
    "验收对照": [
      { "条目": "方案 §4 阶段B", "结果": "✅ | ⚠️部分 | ❌未做", "证据": "命令或文件路径" }
    ],
    "反着验": [
      { "对象": "闸门 ⑥", "注入": "把某 key 改错", "结果": "sync 中断 exit 1", "已还原": true }
    ],
    "静默失败": ["断言通过但样本量为 0 的检查"],
    "引用核实": ["方案里引用的 id / 路径 / 依赖，核实结果"],
    "补做的": ["自检段补上的东西"],
    "未完成": ["补不完的，具体到条目"]
  },

  "review": {
    "审查范围": "本次改动涉及的文件数 / 模块",
    "P0": [{ "位置": "file:line", "问题": "...", "根因": "...", "处置": "已修 | 列入剩余" }],
    "P1": [],
    "P2": [],
    "已修": ["修了什么 + 验证结果"],
    "未修原因": ["为什么留到以后"]
  },

  "验证": {
    "全量跑了": true,
    "总数": 620,
    "分项": { "arch": 35, "graph": 59, "...": 0 },
    "跳过": [],
    "额外": ["编译检查等非 verify 链的验证结果"]
  },
  "数字同步": { "位置数": 4, "是否全同步": true, "实测值": 620 },
  "提交": { "已提交": true, "hash": "abc1234", "message": "feat(icons): ..." },
  "清理": { "调试产物已删": true, "残留": [] },

  "踩的坑": ["..."],
  "给下一棒的话": "..."
}
```

**填写要点**

- `开发.未做完的` 与 `自检.未完成` 不许出现"部分未完成""基本完成"。
  每一条都必须能被第三方用**一条命令或一次 `ls`** 核对。
- `自检.反着验` 若一项都没做，写空数组**并说明原因** —— 不许略过整个字段。
- `review.P0` 为空就写 `[]`，并在 `review.已修` 里说明扫了哪些维度。
- `提交.已提交` 为 false 时，必须说明为什么没提交。
- **禁止在 `未做完的` 里写"其余同前棒"之类的引用式表述** —— 状态文件是独立凭证。

## 二、开发棒 prompt 模板

```
【夜跑 · 第 <N> 棒 / 共 <M> 棒】<任务名>

总规程（必读，开工第一份）：<仓库>\<计划文件夹>\NIGHT-RUN.md
本棒方案：<仓库>\<计划文件夹>\<plan 文件名>
工作目录：<仓库绝对路径>
状态目录：<仓库>\.workbuddy\night-chain\

时间：单棒预算 <X> 分钟（开发 <D> / 自检补漏 <S> / Code Review <R> / 收尾约 20）。
交棒硬线 <HH:MM>。
这不是"尽量做完"，是"在窗口内交付"。到硬线无论做到哪一步，立刻停止开新阶段，执行收尾并交棒。

【第 0 步 · 等前棒】（第一棒删掉本步，改为"你是第一棒，无需等待"）
若 night-chain\<N-1>-done.json 不存在，说明前棒还在跑 ——
**不要开工，不要碰仓库里的任何文件。** 每 60 秒查一次，最多等到 <HH:MM>。
等不到就写 <N>-blocked.json，跳过本棒直接交棒，如实留给终检棒。
绝不能和前棒并行改仓库 —— 两棒同时改同步脚本 / README / 验证数字会互相踩烂。
开工即建 night-chain\<N>-running.json（含本棒砍定后的范围）。

【第 1 步 · 读，不许跳过】
- NIGHT-RUN.md
- <方案文件>
- <项目的索引 / 铁律文件>
- <项目 memory 的 MEMORY.md 与最近三天的日志>
- <上次夜跑的 0N-done.json / REVIEW.md（若有）—— 未完成清单是本次的输入>

【第 2 步 · 砍范围】
按预算把方案砍到 <D> 分钟能做完的规模。方案原文是按"一整晚"写的，砍是正常操作。
优先保 P0 与闭环那一步，扩展项能舍就舍。砍完写进 <N>-running.json。

【第 3 步 · 开发（<D> 分钟）】
<从方案里提炼 3–7 条可验收的核心要求，写死判据>

前置依赖检查：<依赖产物清单>。
缺失就降级 + 如实记入「降级处理的」，**不许硬造**。

【第 4 步 · 自检补漏（<S> 分钟）】
按总规程 §2.3 做五件事：
1. 把方案的「分阶段实施 / 验收标准」逐条拉表，标 ✅ / ⚠️部分 / ❌未做（**对照原文，不是印象**）；
2. 声称新建的文件逐个 ls 确认存在；
3. **反着验 ≥2 处**本次新写的闸门或断言：故意注入错误 → 确认真会红 → 还原；
4. 找"空跑通过"的检查（断言通过但样本量为 0）；
5. 方案里引用的 id / 路径 / 依赖，去仓库核实真实存在。
未完成项**先补**；补不完的写进清单，具体到文件 / 阶段 / 断言编号。

【第 5 步 · Code Review（<R> 分钟）】
按总规程 §2.4 审**本次改动的代码**（不审全仓），五个维度：
正确性 / 安全 / 性能 / 可维护性 / 一致性。
每条按 `[P0/P1/P2] file:line —— 问题 → 根因 → 处置` 记录。
**P0 与便宜的 P1 当场修**，修完重跑验证；其余进清单并写明为什么没修。
不许把 P2 包装成 P1 凑数，也不许漏报。

【第 6 步 · 收尾（顺序不能反）】
1. 跑**全量**验证（不是只跑自己改的那一层），记录真实数字与跳过的层；
2. 同步所有派生数字：<本项目要同步的位置，逐个列出>；改完复跑一次确认生效；
3. **git commit**（message 用 `feat(scope): ...` 规范格式），确认没夹带调试产物；
4. 删掉所有 `_*` 调试产物；
5. 追加 memory 日志；
6. 若构建 / 验证比开工前更红且修不了 → **回滚到开工前状态**并在报告里说明回滚了什么；
7. 写 night-chain\<N>-done.json（schema 见总规程配套的 briefing-templates）。

【第 7 步 · 交棒】
把第 <N+1> 棒「<下一棒任务名>」（id: <automation id>）的执行时间改成「现在 + 3 分钟」。
若预计超时，先推到你预计结束时间 +3 分钟；但不要让终检棒晚于 <硬线>。

环境：<本项目环境备忘，逐条照抄 project-profiles 对应节>

报告：开头写明实际模型名与起止时间 → 先结论（做完 / 做到哪一步）→ 再证据（命令与输出）
→ 再剩余工作量清单。不许把没做完的说成做完了。
```

## 三、终检棒 prompt 模板

```
【夜跑 · 终检棒 / 共 <M> 棒】夜跑巡检与补漏

总规程：<仓库>\<计划文件夹>\NIGHT-RUN.md（职责见 §六）
工作目录：<仓库>
状态目录：<仓库>\.workbuddy\night-chain\

时间：无条件启动 <HH:MM>，硬停 <HH:MM>（约 <X> 分钟）。
窗口外每分钟都在扣积分，不要越线。

你是今晚唯一不写新功能的一棒。产出是「真相」+ 把摊子收拾干净，不是"再做一个功能"。

【第 1 步 · 等（但绝不并行）】
若 night-chain\<M>-done.json 不存在，说明最后一棒还在跑 —— 等到 <HH:MM> 为止；
等待期间**不要碰仓库里任何文件**。等不到就按「第 <M> 棒未交棒」如实记录，然后继续往下做。
绝对不要和工作型任务并行改仓库。

【第 2 步 · 收集】
读 night-chain\ 下全部状态文件（0N-running / 0N-done / 0N-blocked）与各棒报告。

【第 3 步 · 独立验证（不许只信状态文件 —— 这是你的核心动作）】
逐项自己动手验一遍：
- 全量构建与全量验证真跑一遍，记录真实总数、分项与跳过的层；
- 声称新建的文件逐个确认存在；
- **闸门真的在工作**：故意写坏一处，确认真的中断；验完改回来；
- **断言真的在工作**：故意构造反例，确认真的变红；验完改回来；
  ⚠️ 优先验那些**从未红过**的检查 —— 一条从没红过的断言和摆设没有区别；
  四棒都很赶，这里是偷工减料最可能发生的地方；
- 页面真的挂上导航；派生数字真的全部同步；memory 真的写了；
- **git 真的提交了**：各棒是否都形成提交、有没有夹带调试产物、工作区是否干净。

【第 4 步 · 补漏（只补硬停前能补完的，按此优先级）】
1. 仓库不可运行 / 构建失败 → 必须修；
2. 验证挂红 → 修到绿，或如实记录挂红项与原因；
3. 派生数字不同步 → 同步；
4. README / memory 日志缺 → 补上；
5. 状态文件缺 / 工作区脏 → 补齐、清理。
**不补**任何需要 30 分钟以上的新功能开发。宁可如实写"未完成"，也不要开一个必然做不完的头。
绝对不许：为了让报告好看而修改结论、把"没做"写成"做了"、删掉挂红的断言。

【第 5 步 · 产出】
1. 写 night-chain\REVIEW.md，逐棒记：
   该棒自述状态 vs 你独立验证的结果、**差异清单（逐条点名）**、你补了什么、还差什么、
   实测数字（总数 + 分项 + 跳过）；
2. 剩余工作量按**离闭环的距离**排 P0/P1/P2 —— 这份清单是下一晚的输入；
3. 清理一次性状态文件（_running / _blocked 之类），只留 0N-done.json 与 REVIEW.md；
4. 用 present_files 呈现 REVIEW.md。

环境：<本项目环境备忘>

报告：开头写明实际模型名与起止时间 → 先结论 → 再证据（命令与输出）→ 再剩余工作量清单。
```

## 四、编排时的编写要点

1. **每棒 prompt 自包含** —— 夜间 agent 看不到编排对话，也不知道技能存在。
   所有路径写**绝对路径**。
2. **时间预算要写进 prompt** —— agent 才会把它当约束，而不是"参考"。
3. **硬线写具体钟点，不写"约"** —— "约 03:00" 会被理解成可以到 03:40。
4. **环境备忘逐棒重复** —— 漏一条那一棒就废了，不要嫌啰嗦。
5. **第一棒时间设在 23:05 之后** —— 给用户在客户端选模型的时间。
6. **后续棒写"接棒（兜底 HH:MM）"** —— 兜底是保险丝，不是计划开工时间；
   同时把 scheduledAt 设成兜底值（防止前棒静默死掉导致整链停摆）。
7. **每棒都要有交棒动作** —— 显式写明"把第 N+1 棒的 id: xxx 时间改成现在 + 3 分钟"，
   否则 agent 不知道要动哪条任务。
8. **终检棒的硬线要留足** —— 至少 40 分钟，且必须在窗口硬停之前。
