## 2. 浏览器里怎么跑（`@terrastruct/d2` / `@d2lang/d2`）

- 它不是纯 JS 实现，而是 **Go 编译成 WASM 的封装**：`D2.js is a wrapper around the WASM build of D2`。README 明确：`D2.js uses webworkers to call a WASM file.`
  - https://github.com/d2lang/d2/tree/master/d2js/js#readme
- 包已改命名空间：新装用 `@d2lang/d2`，`@terrastruct/d2` 作为兼容包同版本发布。
- 版本与体积（jsDelivr 文件清单，未压缩）：
  - `@terrastruct/d2@0.1.33`：浏览器入口 `dist/browser/index.js` **8.19 MB**；`d2.wasm` 22.07 MB；`elk.js` 3.68 MB；`index.d.ts` 9.9 KB；包 unpackedSize 约 59.8 MB。
  - `@d2lang/d2@0.1.34`：浏览器入口 **11.51 MB**；`d2.wasm` 42.12 MB（新增 TALA）；unpackedSize 约 95.9 MB。
  - https://data.jsdelivr.com/v1/packages/npm/@terrastruct/d2@0.1.33
  - https://data.jsdelivr.com/v1/packages/npm/@d2lang/d2@0.1.34
- 浏览器构建把 WASM **brotli 压缩后 base64 内联**进 JS，运行时用 worker 解码：构建脚本里有 `brotliCompressSync` → base64 → `wasm-loader.browser.js`，`platform.browser.js` 的 `loadFile("./d2.wasm")` 直接返回内存二进制。因此**首次不需要任何网络请求、不需要 Node 服务端**，静态托管（`python -m http.server`）可用。
  - https://github.com/d2lang/d2/blob/master/d2js/js/build.js
  - https://github.com/d2lang/d2/blob/master/d2js/js/src/platform.browser.js
  - https://github.com/d2lang/d2/blob/master/d2js/js/src/worker.browser.js
- 官方用法：
  ```js
  import { D2 } from '@d2lang/d2';
  const d2 = new D2();
  const result = await d2.compile('x -> y', { sketch: true, layout: 'elk' });
  const svg = await d2.render(result.diagram, result.renderOptions);
  await d2.dispose();
  ```
- 注意事项：浏览器版通过 `new Worker(URL.createObjectURL(new Blob([...])))` 建 worker，需要 CSP 允许 `worker-src blob:`；且必须客户端执行（Next.js 中 `dynamic import` + `ssr: false`），不能在预渲染期跑。

## 3. 能不能不手写 DSL

**在 JS 里必须拼 D2 脚本字符串。** `compile()` 的签名只接受 `string` 或 `{ fs: Record<string,string>, inputPath, options }`（虚拟文件系统方式支持 `@import`），没有任何“从对象图构建”的 API。
- https://cdn.jsdelivr.net/npm/@terrastruct/d2@0.1.33/index.d.ts
- 官方的程序化构图 API 是 **Go 专用**：`d2/d2oracle`（Create/Set/Delete/Rename/Move）——`D2 has an API built on top of its AST for programmatically creating diagrams in Go.`
  - https://d2lang.com/tour/api
- 核心语法（需自己生成并转义）：`a -> b: label`；容器 `backend: { api: ... }`；键值属性 `{shape: cylinder; style.fill: "#e3e9fd"; style.border-radius: 8; icon: https://...}`；样式块 `style: {stroke: ...}`；方向 `direction: right`；网格 `grid-rows: 2 / grid-columns: 3`；类与变量 `classes: {...}`、`vars: {}`。
  - https://d2lang.com/tour/grid-diagrams
  - https://d2lang.com/tour/style
  - **坑**：D2 语法里 `: ; { } # . * & | @ "` 等在 ID/label 中有语义，中文字符串与 `:` 组合时必须加引号或做 normalize，否则解析失败——脚本生成层要专门写转义/校验。

## 4. 输出格式

- JS API：`render()` 返回 **SVG 字符串**（`Promise<string>`），另有 `ascii`/`asciiMode` 纯文本输出。
- **PNG 不在浏览器 JS API 内**：PNG/GIF/PDF/PPTX 是 v0.9.0 起 CLI 内置渲染器的能力（`exports: render PNG, GIF, PDF, and PPTX with the built-in renderer`）。要 PNG 只能二选一：浏览器内用 canvas 走 SVG→PNG（`drawImage` + `toBlob`），或构建期/本地调 CLI（用户有 Windows + Node 22 + Python 3.11 + Git bash + JDK 17，可装 d2 MSI/bin）。
  - https://github.com/d2lang/d2/releases/tag/v0.9.0
- 拿到的 SVG 可直接 `Blob` 下载、也可直接写进 zip（`noXMLTag: true` 便于内联 HTML）。多次渲染同一页面记得传 `salt` 避免 ID 重复。

## 5. 好看程度与可定制性

- 官方口号：`D2 comes with many themes that make your diagram look professional`，内置多套主题 + 官方主题总览图；支持 `themeID` / `darkThemeID`，以及 `theme-overrides` / `dark-theme-overrides` 覆写配色（可完全自定义主题）。
  - https://d2lang.com/tour/themes/
  - https://d2lang.com/tour/themes/#customizing-themes
- `sketch: true` 手绘模式（默认手绘字体为 Architect's Daughter + Fuzzy Bubbles 混合）。
  - https://d2lang.com/tour/sketch/
  - https://d2lang.com/tour/fonts
- 分层架构图效果：容器嵌套是原生能力；官方 TALA 发布博客给出 7 组「同一份源码、三种布局引擎」的架构图对比 SVG（含 Fulcro RAD、Jupyter on AWS EKS、Go Queue worker 等），可直接看效果：
  - https://www.d2lang.com/blog/tala-is-open-source/
- 样式可控项（来自 `index.d.ts` 的 `Style`）：`fill`、`stroke`、`strokeWidth`、`strokeDash`、`borderRadius`、`shadow`、`3d`、`multiple`、`doubleBorder`、`font`、`fontSize`、`fontColor`、`bold`、`italic`、`underline`、`animated`、`opacity`、`fillPattern`；形状有 `icon`/`iconPosition`。图标可用 URL 或内置形状。
- 客观评价：默认主题（0 号）配色克制、偏工程文档风，不是设计稿级；但「主题 + 覆写 + 圆角/阴影/图标 + 字号」的组合足以做到「像样的企业分层架构图」，代价是需要自己调一套主题。

## 6. 布局引擎

三种，`CompileOptions.layout`：`'dagre' | 'elk' | 'tala'`，默认 `dagre`。
- **dagre**：默认，快，专门「Renders hierarchical layouts well」，算法源自 Graphviz，但官方明确列出缺点：2018 年后无维护、多段连线是曲线而非正交（会出现不好看的波浪线）、容器的子节点连到另一容器原生不支持（D2 打了 shim）。且 **「Connections from ancestors to descendants（容器连自己的子节点）在 Dagre 下不可用」**。
  - https://d2lang.com/tour/dagre
  - https://d2lang.com/tour/layouts/
- **ELK**：官方评价更成熟、维护更好，分层方向同样是一次性的全局 `direction`（`up/down/right/left`）。
- **TALA**（0.9.0 起开源内置，MPL-2.0）：专为软件架构图设计的正交布局引擎，支持 `top`/`left` 精确定位、支持**每个容器单独设 direction**。缺点官方自陈：算法有随机性（默认 3 seeds，加一个节点整图可能大变）、不如 Dagre/ELK 擅长长链 DAG、大图运行时间非线性增长。
  - https://www.d2lang.com/blog/tala-is-open-source/
- 「同一层方块并排」：容器内并排是默认行为；需要严格等宽可用 `grid-rows` / `grid-columns`（`grid-gap`、`vertical-gap`、`horizontal-gap`）。
  - https://d2lang.com/tour/grid-diagrams
- **版本红线**：`layout: "tala"` 只在 **0.1.34**（含 TALA）可用；0.1.33 没有 TALA。

  - https://api.github.com/repos/d2lang/d2
  - https://api.github.com/repos/d2lang/d2/releases
  - https://registry.npmjs.org/@d2lang/d2
- **JS 包至今没有正式 stable 发布**：README 的 Publishing 一栏写着 `TODO stable release publishing.`，版本号长期停在 0.1.x。
  - https://github.com/d2lang/d2/tree/master/d2js/js#readme
- 0.1.34 changelog（本包自己的变更日志）重点：支持 D2 0.9.0 与 TALA、新增 `D2.dispose()`、修复同一实例并发调用、修复 Unicode 字符后的补全、修复 theme-overrides、修复 ELK 布局下的 grid、修复 TS 签名，并声称 `Significantly reduce bundle size`；但实测浏览器入口从 8.19 MB 涨到 11.51 MB、WASM 从 22 MB 涨到 42 MB，**该“减体积”表述与实测不符**，选型时以实测为准。
  - https://github.com/d2lang/d2/blob/master/d2js/js/CHANGELOG.md
- 静态导出/路径风险：browser 构建自包含、不发二次请求，因此**没有路径问题**；风险集中在 (a) 主 chunk 8–12 MB 的下载/解析首屏成本，(b) 需要 blob worker 的 CSP，(c) 不能用 SSR/预渲染期执行，需 `ssr: false` 动态导入。
- 字体/体积风险：WASM 内含字体子集，所以渲染出的 SVG 自带 `@font-face` base64 字体；多张图同页会重复内嵌样式与字体（官方 issue #1187 承认冗余）。
  - https://github.com/d2lang/d2/issues/1187

## 8. 中文支持

- **真实存在的坑（有官方 issue）**：当某个字重/斜体在所用字体里缺字形时，SVG 里嵌入的字体不含该字形，浏览器会回退到系统默认字体（该 issue 作者在 Edge WebView 上退成 Times New Roman），而 D2 是按自己字体的度量算好的布局，于是**文字显示/宽度与排版不一致**；issue 明确说 `naive use of AddFontStyle is apparently not sufficient`（用 D2 当作库时自定义字体流程缺乏文档）。
  - https://github.com/d2lang/d2/issues/2602
- 默认字体链是 Source Sans Pro（正/斜/粗/半粗）+ Source Code Pro（代码/UML）+ 手绘字体，**均不含 CJK 字形**，所以中文标签必然落在「缺字形回退」这条路径上，必须自带中文字体。
  - https://d2lang.com/tour/fonts
- JS 侧替代方案：`CompileOptions.fontRegular / fontItalic / fontBold / fontSemibold` 传 `.ttf` 的 `Uint8Array`。**已知 bug**：d2js 0.1.23 下只要传任一 `font*` 就报 `invalid JSON input`（该 issue 至今 open，未标注修复版本），0.1.27+ 未查证是否修好。
  - https://github.com/d2lang/d2/issues/2522
- **未查证**：D2 对中文的**换行点**与**字宽计算**是否有专门处理（在 `d2lang/d2` 中用 `chinese`/`CJK`/`中文` 检索标题均无命中；未找到针对 CJK 的宽度或断行 issue）。结论：需要自己实测「中文标签宽度是否与渲染框匹配」，并准备好用显式 `width`/`height` 兜底。

## 结论

**评分：勉强（可用，但不算「合适」）。**

一句话理由：D2 在浏览器端确实能完全离线地把 D2 脚本渲染成好看的 SVG 分层架构图（WASM + worker，静态导出无障碍，主题/sketch/网格/容器/三种布局引擎都齐），但它在 JS 侧**没有任何从数据结构直接建图的 API**，你必须自己写一个「17 槽位 → D2 脚本字符串」的生成器并处理语法转义，同时默认字体不含中文、缺字形回退会破坏布局，必须自带中文 TTF 走 `font*` 参数（该参数还有未修的 bug），这让「从结构化数据渲染」这条主链路的集成成本明显偏高。

主要代价：
- **Bundle 体积**：浏览器入口 chunk 8.19 MB（0.1.34 为 11.51 MB），解压后 WASM 22 MB / 42 MB。这是**绝对体积**而非 gzip 后体积，首屏必须懒加载 + 加载态。
- **PNG 需自己补**：JS API 只给 SVG/ASCII，PNG 得靠 canvas 转换或构建期调 CLI。
- **中文需自备字体**：默认字体无 CJK，且字重不全导致的回退会与布局度量不一致。
- **集成复杂度**：脚本生成层（转义/引号/normalize）+ blob worker 的 CSP + `ssr: false` 动态导入 + 主题定制，约等于一个独立子系统。

更省事的替代路线（同为「有数据 → SVG 字符串」，但原生 JS、无 WASM、体积小一个数量级）：直接用 `@dagrejs/dagre` 或 `elkjs` 自己算布局 + 手写 SVG（或 React 组件）渲染——分层方向、层内并排、圆角/配色/中文全在你自己的掌控里，代价是视觉打磨要自己做。若这个项目的核心诉求是「**导出包里的架构图要好看、可复现**」，把 D2 用在**构建期**（本地 CLI 预渲染成 SVG 资源，或把 D2 脚本作为可选导出格式）会比把它塞进浏览器运行时更划算。
