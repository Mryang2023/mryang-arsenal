**日期**：2026-10-16
**代号**：`项目工坊`（一级菜单组）+ 后端项目注册表与代码缓存
**用户原话要点**：展示性内容（规则库、场景案例）与「要选项目才能用」的功能（项目侦察、测试工程师）混在一级菜单；希望后两者收进同一个一级菜单，用之前**必须先选一个固定项目**，项目代码**先进缓存**，两个功能都走缓存处理（更快）；不许再用临时地址，切菜单不许丢内容。

## 0. 结论先行

| # | 决策 | 一句话理由 |
|---|---|---|
| D1 | 新一级菜单组 **「项目工坊」**，含三个子项：**项目管理 `/projects`（新页）/ 项目侦察 `/autopsy` / 测试工程师 `/qa`** | 用户明说「在项目管理那里选择一个固定的项目」→ 项目管理是组的第一个子项，两个功能页只认当前项目 |
| D2 | `/autopsy`、`/qa` **路由不变**，只新增 `/projects` | shoot.mjs 矩阵、外链、既有留档全部不作废；视觉层只 +1 固定页 |
| D3 | 两个功能页**移除「填地址」输入**（含 zip 上传模式），换成「当前项目卡」 | 临时地址是用完即弃的根源；zip 建项目一期不做（上传是 multipart，与摄取的原子性语义冲突，要建项目先解压到本地） |
| D4 | 添加项目 = **摄取进服务器侧缓存**（path 复制 / git clone），之后一切操作读缓存 | git 项目现状是**每发一次请求就 clone 一遍临时目录、用完即删**（`SourceResolver.fromGit`）—— 这是「慢」的大头；缓存同时解决「侦察与测试工程师读的不是同一份码」的 skew |
| D5 | 注册表服务端 `.data/projects/registry.json`；「当前项目」选择记浏览器 localStorage | 注册表是缓存的属主，必须与缓存同址；当前选择是会话偏好，照 `picks-store.ts` 的跨页总线先例 |
| D6 | **统一 projectId 算法**为 `sha256(kind+":"+规范化脱敏值)` 前 12 位 | 现状是两套：后端 QA 用 sha256-12，前端快照用 FNV-1a（`pj-…`）——同一地址在两边算出两个身份，历史永远对不上。以后端算法为准（既有 `.data/qa/<id>/` 历史不作废），Node 侧同改 + 旧 `pj-` 快照一次性 rekey |
| D7 | 内容不丢 = **服务端按项目留档 + 挂载即恢复** | facts 缓存、体检 latest+history、QA 最新报告、RUNNING job 续跑；切菜单再回来，内容是从服务端读回来的，不是组件 state |
| D8 | `/archify` 的「从代码生成」**保持临时地址不动** | 范围控制；它已有离线粘贴 facts 的路，迁不迁是另一个计划 |

## 2. 项目管理页（/projects）产品规格

### 2.1 功能清单

| 功能 | 行为 | 边界与话术 |
|---|---|---|
| 添加项目 | 名字 + 类型（本地目录 / https git）+ 地址 → 「摄取」→ 进列表 | 重复 projectId → 409 并指向已存在项，不静默覆盖 |
| 摄取 | path：复制整树进缓存；git：clone 进缓存。落 `.ingest-tmp/` 后**原子改名** | 限额与扫描同源不新开：单文件 2MB / 总 500MB / 2 万文件 / 深度 20；超限**整份拒绝**，不留半份缓存 |
| 设为当前 | 全局唯一「当前项目」，写入 localStorage；侧栏组标题下显示当前项目名 | 后端离线也能设（它是本地偏好），但两个功能页会在加载时报离线 |
| 缓存状态 | 文件数 / 字节 / 摄取时间 / 树指纹 / 最近刷新与 diff 计数 | 「缓存于 X」≠「与源头一致」，两句话分开发 |
| 源头新鲜度 | path：服务端 walk 源头按 mtime+size 与 manifest 比对 → 新增 N / 变更 N / 消失 N；git：一期「未检测，点刷新同步」 | 未检测就说未检测，不许显示一个绿的「最新」 |
| 刷新缓存 | path：按 manifest 增量同步（增/改/删）；git：`fetch --depth 1` + reset，失败则缓存不动 | fetch 失败 → 旧缓存原样保留 + 明说「刷新失败，用的还是 X 时的缓存」 |
| 删除 | 摘注册项 + 删缓存/facts/体检留档；**QA 历史报告保留**（`.data/qa/<id>/` 是审计痕迹） | 删除确认框里写清「QA 历史报告会留下」 |
| 行内入口 | 每行「打开侦察」「打开测试工程师」 | 点击即把该项目设为当前并跳转 |
| 空态 | 首次进入引导添加第一个项目 | 不给假示例数据 |
| 离线态 | 后端不可达 → 明说「项目工坊整组功能需要后端 :3011」 | 与 `/qa` 现有离线话术同族 |

### 2.2 页面信息架构（单页，不拆子页）

一屏四区：① 当前项目横幅（名字/来源/缓存时间/新鲜度/切换按钮）② 添加项目表单 ③ 项目列表（表格：名字、类型、地址(脱敏)、缓存状态、新鲜度、最近 QA、操作）④ 底部说明（限额、缓存位置、删除语义）。移动端表格降级为卡片行——沿用站点既有响应式套路，不新造。

## 3. 代码缓存：数据模型与存储

### 3.1 存储布局（全部不进 git）

```
.data/projects/
  registry.json                  # 注册表（原子写：临时文件 + move）
  <projectId>/
    repo/                        # 代码缓存：摄取那一刻的稳定快照（只读，活体采集另复制到临时工作副本）
    manifest.json                # path 项目专用：relpath → {size, mtimeMs}（刷新/新鲜度比对用）
    facts.json                   # 最近一次扫描的事实 + meta{scannedAt, elapsedMs, fingerprint}
    checkup-latest.json          # 最近一次体检报告
    checkup-history/<id>.json    # 体检历史（封顶 20 份，超出删最旧）
```

- 目录三档解析，照 `charter-dir.mjs` 先例：默认 `.data/projects/` < `arsenal.json#project.projectsDir` < 环境变量 `ARSENAL_PROJECTS_DIR`。
- `.gitignore` 增加 `**/.data/projects/`（⚠️ 必须带 `**/` 前缀——`.data/qa/` 那条 2026-10-12 踩过锚定坑，见 `.gitignore:30-40` 注释）。
- **缓存永远不在被扫描的仓库里**；活体采集的不变量不变：编译产物写临时副本，不写缓存（`AutopsyController.toWorkCopy` 的既有理由）。

### 3.2 registry.json 数据模型

```json
{
  "schemaVersion": 1,
  "projects": [
    {
      "id": "a1b2c3d4e5f6",
      "name": "order-service",
      "source": { "kind": "path", "value": "D:/work/order-service" },
      "note": "",
      "addedAt": "2026-10-16T23:30:00+08:00",
      "cache": {
        "files": 812, "bytes": 4188392,
        "ingestedAt": "2026-10-16T23:30:04+08:00",
        "fingerprint": "dir:812:4188392",
        "lastRefresh": null,
        "lastDiff": null
      },
      "lastFactsAt": null,
      "lastJobId": null
    }
  ]
}
```

- `source.value` **先脱敏再存**（`redactSourceValue`：`https://u:<token>@…` → `https://u:***@…`），projectId 同样在脱敏后计算 —— 带令牌与不带令牌的同一仓库必须是同一个项目。
- `lastJobId` 由 QA submit 写入，是「切走再回来续跑」的唯一线索。
- 单用户工具：并发写用「写临时文件 + move」保证原子；读失败返回空列表并明说，不崩。

### 3.3 新增 API（全部 `/api/projects`，三态口径与 `arsenal-api.ts` 一致）

| 方法 | 路径 | 请求 | 响应 / 失败话术 |
|---|---|---|---|
| GET | `/api/projects` | — | 列表（摘要，**不 walk 源头**） |
| POST | `/api/projects` | `{name, source:{kind,value}}` | 摄取成功后回项目 + 缓存统计；409 = 已存在同 id 项目；限额超限 = 400 + 具体哪项超了 |
| GET | `/api/projects/{id}` | — | 详情 + 新鲜度（walk 源头）；404 = 项目不在了 |
| POST | `/api/projects/{id}/refresh` | — | `{added, updated, removed}`；源头不可达 = 400 + 缓存未动 |
| DELETE | `/api/projects/{id}` | — | 204；QA 历史保留（响应体明说） |
| GET | `/api/projects/{id}/facts` | — | 缓存事实；404 = 还没扫过 |
| POST | `/api/projects/{id}/scan` | — | 重扫缓存 → 更新 facts 缓存，返回 facts |
| GET | `/api/projects/{id}/checkups` | — | 体检历史摘要列表（无内嵌整报告） |
| GET | `/api/projects/{id}/checkups/latest` | — | 最近一次体检；404 = 还没体检过 |
| POST | `/api/projects/{id}/checkup` | — | 跑一次体检（读缓存）→ 写 latest + history |

### 3.4 既有接口改造（向后兼容，二选一入参）

`POST /api/scan/facts`、`/api/autopsy/inspect`、`/api/autopsy/run`、`/api/qa/submit` 请求体在原有 `{source:{kind,value}}` 之外，新增收 `{projectId}`：

- 收敛点只有一个：新的 `ProjectCache.resolve(projectId) → Path root`，四个 Controller 共用，不各自解析。
- 传 `projectId` 时：扫描/体检/深检全部读**缓存根**；QA 的 CLONING 段退场（不再 clone），job 直接从 SCANNING 起。
- 传 `source` 的老路**逐字节不变**（`/archify` 的 CodeIntake、CLI、既有调用方不受伤）。
- 活体采集：工作副本从缓存复制（仍然另建临时目录，缓存只读）。

### 3.5 指纹与增量（服务端做浏览器做不到的那件事）

- `TreeFingerprint`（Java）：walk 目录取 mtime+size 树哈希，**不读文件内容**（与 Node 侧 `autopsy-fingerprint.mjs` 同口径）。
- path 项目：摄取时写 manifest；刷新/新鲜度 = 逐文件比 mtime+size，只复制变化的。
- git 项目：指纹 = `HEAD` commit（摄取/reset 时记）。
- 页面上「已与源头比对」只在真比过之后出现；比不了（git 一期）就说「未检测」。

## 4. 两个功能页改造规格

### 4.1 共用：「当前项目卡」取代「填地址卡」

```
┌ 当前项目 ────────────────────────────────────────────┐
│ ◈ order-service   本地目录 · D:/work/order-service     │
│ 缓存：812 文件 · 4.0 MB · 摄取于 23:30 · 已比对源头(0 变) │
│ [刷新缓存] [检查源头变化] [重新扫描] [切换项目]           │
└──────────────────────────────────────────────────────┘
```

- 无当前项目 → **守卫空态**：「这两个功能依托于固定项目。先到「项目管理」选一个。」+ 跳转按钮。没有地址输入框，临时路线退场。
- 当前项目被别处删了 → 详情 404 → 「项目不在了」+ 去项目管理。
- 后端离线 → 卡片照显（本地存的名字/来源），内容区报离线（既有话术，不新造）。

### 4.2 项目侦察（/autopsy，七个页签不动）

| 页签 | 改造 |
|---|---|
| 架构面板 | 挂载即 `GET facts 缓存` → 直接出图；空则引导「一键分析」。「一键分析」语义变为**重扫缓存**（不是重扫源头）；原「强制重扫（不用缓存）」按钮退场 |
| 服务拓扑 / 功能视图 | 同 facts 缓存驱动，无独立输入 |
| 体检报告 | 挂载即 `GET checkups/latest`；「一键体检」= `POST checkup`（读缓存）并写 history；L1 复用判据从「用户说没变」升级为**「缓存指纹 + 规则集版本」双键未变**（服务端可比，规则集或 checkups.json 动过就不许复用） |
| 历史 | 改读服务端 `GET checkups` 列表；浏览器旧快照保留只读，标记「旧本地留档」 |
| 生命体征 | 一期保留浏览器侧序列（localStorage 本就跨导航存活，key 换成统一 projectId）；二期可从服务端 history 现算 |
| 活体对账 | 入口清单来自缓存 facts；工作副本从缓存复制；zip 模式随临时地址一起移除 |
| 「这次扫的是哪儿」面板 | 从「输入 vs 实际扫描」改为「源头 → 缓存 → 本次结论」三段链：源头地址、缓存摄取时间与指纹、本次结论的扫描时间 |

### 4.3 测试工程师（/qa，四面板不动）

- 挂载：`GET snapshots?projectId` → 最新报告直接呈现（含 A/B/C/D 四面板与委员会）；没有 → 空态引导「开始审查」。
- **断点续跑**：registry.lastJobId → `GET /api/qa/jobs/{id}`；状态 PENDING/RUNNING → 自动续轮询（1.5s 一跳，既有循环逻辑原样复用）；FAILED → 照实报。
- 提交：`{projectId, range, deepCheck}`；范围圈选的目录树来自 `qaTree(projectId)`（不重新 clone，既有接口）。
- 历史列表：照旧读服务端 `.data/qa/<projectId>/`。
- 头部横幅加一行「本项读缓存，源头变化请先刷新缓存」——把「报告对应哪份码」说死。

### 4.4 诚实口径（本仓铁律，一条不破）

1. 「缓存于 X」≠「与源头一致」；未比对就说未比对，比对出 N 个变化就报 N。
2. 0 文件 / 被闸门截断的缓存 → 指纹不可信，标记并不许用于复用判据（沿用 `fingerprintTrust` 判据，服务端同款）。
3. QA 报告「未覆盖 ≠ 通过」、覆盖率带分母 —— 既有口径不动。
4. 刷新失败时旧缓存必须标注为旧（时间戳是摄取时间，不是刷新时间）。
5. 删除项目后 QA 历史成为「游离档案」，删除确认框与列表残留提示都要写。

**端到端冒烟脚本**（本机 java 常驻坑，照 memory 探活姿势：启动 + sleep 13 + fetch + kill 放同一条 bash）：起后端 → POST 添加 path 项目 → GET facts → POST checkup → POST qa/submit → 轮询到 DONE → GET latest → refresh → 再 GET facts。每步断言响应码与关键字段，失败即红。

## 8. 风险与待拍板（开工前要用户点头的）

| # | 事项 | 推荐 | 代价/备选 |

| R1 | 组名 | **项目工坊** | 备选：项目中心 / 项目台。与「装配台」同族，一眼看出是干活的地方 |

## 9. 明确不做（范围锁定）

1. 不动 `/archify`「从代码生成」的临时地址输入（迁移路径记着，另开计划）。
2. 不做 L2 文件级增量重算 facts（refresh 同步缓存后全量重扫缓存即可，先把 L1 做诚实）。
3. 不做文件 watcher 自动刷新（CLI `autopsy-watch` 已存在，网页端不做）。
4. 不做多项目并排对比视图。
5. 不改 QA 的语义深检/委员会/实锤任何判定逻辑（只换输入源与恢复现场）。
6. 不做 MCP/CLI 新出口（P2，另册）。
