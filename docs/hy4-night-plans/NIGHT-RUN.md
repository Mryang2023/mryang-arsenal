# 夜跑常驻规程

> **性质**：本项目夜间无人值守开发的**常驻作业规程**。每次夜跑都读它。
> 具体某一晚的棒次表、时间硬线、任务清单**不在这里** —— 那些写在每棒的 prompt 里。
> 本文件只管「一棒怎么干才算干完」。
>
> **工作目录**：`D:\workspace\2026\mryang-arsenal`
> **状态目录**：`D:\workspace\2026\mryang-arsenal\.workbuddy\night-chain\`
> **计划文件夹惯例**：`docs\hy4-night-plans\`
>
> 立规：2026-09-22（依据 2026-09-21 首次夜跑的实测结果）。
> 章程权威版在技能 `night-run` 的 `references/charter.md`；本文件是它在本项目的实例。

---

## 一、性质与窗口

- 夜跑走 **23:00 → 次日 08:00** 这段夜间免费窗口。**硬停时间由编排者指定**（惯例 07:55）。
- 这不是 N 条独立任务，是**一条接力链**。前一棒不交棒，后一棒不许开工。
- 窗口外的每一分钟都在扣积分。到硬线无论做到哪一步，立刻停止开新阶段，执行收尾并交棒。

**为什么串行**：多棒要改同一批文件（`sync-content.mjs` / `README.md` / verify 数字 / 共享类型）。
两棒并行 = 互相踩烂，事后无法归因是谁改坏的。串行的代价是晚开工，并行的代价是静默损坏。

---

## 二、接力协议

### 开工（在读方案之前先做完）

1. 读 `night-chain\` 下已有的状态文件，先搞清现在到第几棒了。
2. **等前棒（最关键的一条）**：`<N-1>-done.json` 不存在 → **不许开工，不许碰仓库任何文件**，
   每 60 秒查一次，最多等到本棒硬线。
   - 等到了 → 正常开工。
   - 等不到 → 写 `<N>-blocked.json`（记录等了多久、前棒缺什么），
     然后**跳过本棒直接交棒**，把问题如实留给终检棒。
   > **绝不能和前棒并行改仓库。**
3. 建 `<N>-running.json`：`{ "棒次": N, "任务": "...", "开工": "<ISO>", "计划交棒": "<ISO>", "砍定范围": "..." }`
4. 第一棒不需要等待。

### 交棒

把下一棒的 `scheduledAt` 改成「现在 + 3 分钟」。
即使"现在 + 3 分钟"已经晚于下一棒的硬线，也照设 —— 让下一棒自己判断还来不来得及。

## 三、一棒三段（缺一不可）

**一棒 = 开发 → 自检补漏 → Code Review。**
这不是"可选的最后两步"，这是**交付的定义** —— 没跑过自检和 review 的产出，不算这一棒做完了。

| 段 | 预算 | 对准 | 回答什么 |
|---|---|---|---|
| 开发 | 60% | 方案的实施计划 | 该做的做出来了吗？ |
| 自检补漏 | 20% | **方案**（要求） | 该做的都做了吗？有没有静默失败？ |
| Code Review | 20% | **代码**（实现） | 写得住吗？有隐患吗？和项目一致吗？ |

收尾另算（约 20 分钟），见 §四。

### 3.1 开发

- **开工先砍范围**，砍到开发预算内。方案原文按"一整晚"写，砍是正常操作，不是偷懒。
  砍完写进 `<N>-running.json`，收工时对照它交账。
- 前置依赖缺失 → **降级 + 如实记录，不许硬造**。
- 阶段化推进（数据 → 引擎 → 产物 → 页面 → 验证），每阶段做完立刻验收。

### 3.2 自检补漏（完整性）

**目标：找出"看起来完成、实际没完成"的地方。** 必做五件事：

1. **验收对照** —— 把方案的「分阶段实施 / 验收标准」逐条拉成表，标 ✅ / ⚠️部分 / ❌未做。
   **对照的是方案原文，不是自己的印象。**
2. **存在性核验** —— 声称新建的文件，`ls` / `grep` 逐个确认真的在。
3. **反着验 ≥2 处** —— 挑本次新写的闸门或断言，**故意注入错误**，确认真会红，然后还原。
   > 一条从没红过的断言，和摆设没有区别。
   > 首次夜跑只验了 2 组，闸门 ⑥⑦、断言【11】【15】、`verify:cases` 25 项、
   > `verify:scan` 恶意输入 7 项至今**未被证伪**。
4. **静默失败排查** —— 找"断言通过但样本量为 0"的检查。
   例：`【11】` 的体积断言在位图 0 张时"通过"；断言 ⑦ 取到 0 条引用却报"0 个全部可解析"。
5. **引用核实** —— 方案里引用的 id / 路径 / 依赖，去仓库查是否真实存在。

未完成项**先补**；补不完的写进清单，具体到文件 / 阶段 / 断言编号。

### 3.3 Code Review（质量）

审**本次改动的代码**（不审全仓），五个维度：

| 维度 | 查什么 |
|---|---|
| 正确性 | 边界值、空值、并发、错误路径、类型、异步时序 |
| 安全 | 注入、路径逃逸、敏感信息硬编码、权限、对外部输入的信任 |
| 性能 | 循环内 IO、N+1、无界集合、重复计算、不必要的同步 |
| 可维护性 | 重复代码、魔法数、命名、死代码、**残留调试代码** |
| 一致性 | 与项目既有范式 / 类型体系是否一致；有没有留下"功能等价但形态不同"的平行通道 |

每条按 `[P0/P1/P2] file:line —— 问题 → 根因 → 处置` 记录。
**P0 与便宜的 P1 当场修**，修完重跑验证；其余进清单并写明为什么没修。
不许把 P2 包装成 P1 凑数，也不许漏报。

### 3.4 段间门禁

| 关卡 | 规则 |
|---|---|
| 开发 → 自检 | `npx tsc --noEmit` 或 `npm run build` 能过 |
| 自检 → Review | 无未修的 P0 完整性缺陷 |
| Review → 收尾 | 无未修的 P0 代码缺陷 |

> **不许带着已知的重病往下走。** 轻问题可以记账前行，重问题不行。

## 四、收尾清单（每棒必做，顺序不能反）

1. **跑全量验证**（`npm run verify` 八层，不是只跑自己改的那一层），记录真实数字与跳过的层。
   **没跑过就不能说它是绿的。**
2. **同步四处 verify 数字**（见 §六），改完复跑一次确认生效。
3. **git commit** —— 本棒产出必须在收工前形成一次提交，message 用 `feat(scope): ...` 格式，
   确认没夹带调试产物。
   > 一夜不提交 = 没有版本快照。中途某棒改坏了，无法回滚到棒间状态。
4. **清理调试产物** —— `.workbuddy\_*` / `arsenal-web\.workbuddy\_*` / `.verify\_tmp-*` 全删。
5. **追加 memory 日志** —— `.workbuddy\memory\<今天>.md`。
6. **回滚判断** —— `build` 或 `verify` 比开工前更红且修不了 → **回滚到开工前状态**并在报告里说明。
   留一个坏状态比少做一个功能严重得多。
7. **写 `<N>-done.json`** —— 必含 `开发` / `自检` / `review` / `验证` / `数字同步` / `提交` / `清理` 七组字段。
   `开发.未做完的` 不许写"部分未完成"，必须具体到**文件 / 阶段 / 断言编号**，能被一条命令核对。

---

## 五、终检棒

**唯一不写新功能的一棒。产出是「真相」+ 把摊子收拾干净。**

1. **等（但绝不并行）** —— 最后一棒没交棒就等到硬线，等待期间不碰任何文件。
2. **收集** —— 读 `night-chain\` 全部状态文件与各棒报告。
3. **独立验证（核心动作，不许只信状态文件）**：
   `npm run build` + `npm run verify` 真跑一遍；声称新建的文件逐个确认；
   **闸门 / 断言故意写坏一次，确认真会红**（优先验从未红过的）；
   页面真挂上导航；四处数字真同步；memory 真写了；**git 真提交了、工作区干净**。
4. **补漏**（按优先级）：仓库不可运行 > verify 挂红 > 数字不同步 > 文档缺失 > 状态文件缺失。
   **不补**需要 30 分钟以上的新功能。
   **绝对不许**为了让报告好看而改结论、把"没做"写成"做了"、删掉挂红的断言。
5. **产出 `REVIEW.md`** —— 逐棒记「自述 vs 独立验证」+ **差异清单（逐条点名）** +
   补了什么 + 剩余工作量（**按离闭环的距离**排 P0/P1/P2，这份是下一晚的输入）。
   清理一次性状态文件，只留 `0N-done.json` 与 `REVIEW.md`。用 present_files 呈现。
6. **硬停** —— 到点无条件停止动手。窗口外每分钟都在扣积分。

## 六、项目铁律与环境备忘

### 环境备忘（每条命令前都要）

- **bash 的 PATH 是坏的**，每条命令前必须：
  `export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Windows:$PATH"`
  不加则 `ls` / `dirname` / `head` 全部 command not found。**已实测有效。**
- node：`C:\Users\Administrator\.workbuddy\binaries\node\versions\22.22.2-3\node.exe`
- python：`C:\Users\Administrator\.workbuddy\binaries\python\versions\3.13.12\python.exe`
- JDK17：`C:/Users/Administrator/.jdks/corretto-17.0.12`

### 铁律

1. **事实源只能是 `tools\content\*.py`。** 改完必跑
   `python tools\build-content.py` → `node arsenal-web\scripts\sync-content.mjs`。
   **闸门中断是在救你，别绕过去。**
2. **写 JSON 一律 `newline='\n'`**，否则整份文件变「CRLF 假变更」。
3. **verify 数字同步四处**：
   - `arsenal-profiles\arsenal.json` → `project.verifyChain`
   - `arsenal-web\.verify\project-check.ts` 手写总数常数
   - `README.md` 总数句
   - `README.md` 分项表
   改完 `arsenal.json` **必须重跑 `sync-content.mjs` 才生效**。
4. **零外部依赖是硬约束** —— 运行时依赖只有 `next / react / react-dom`。
   不许引入图标库 / 动画库 / 图表库 / 滑杆库 / 绘图库。
5. **新模块必须登记进生成器**（如 `tools\build-content.py` 的 `STACK_MODULES`）—— 漏了等于没写。
6. **方案里引用的规则 id 必须去 `arsenal-rules\` 查**，不许照抄方案示例。

## 七、给用户的注意事项（不是给 agent 的）

1. **模型必须手动选** —— 创建接口没有 model 字段，只能在客户端界面逐条选。
   不选就用默认模型跑，整夜按默认倍率扣积分。
2. **电脑必须开机 + 客户端保持登录** —— 定时任务在本机客户端执行，关机即不执行、不补跑。
   「允许锁屏运行」建议设 **"熄屏后继续运行"**（跑满 9 小时，别设屏幕常亮）。
3. **排期取舍由编排者事先说明** —— 哪几条进了今晚、哪几条排到后面、为什么这么砍。
   未完成的部分如实留在各棒 `0N-done.json` 与终检 `REVIEW.md`，是后续夜跑的输入。
