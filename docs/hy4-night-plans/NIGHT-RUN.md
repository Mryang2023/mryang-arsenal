## 二、接力协议（每一棒都必须执行）

- 工作目录：`D:\workspace\2026\mryang-arsenal`
- 状态目录：`D:\workspace\2026\mryang-arsenal\.workbuddy\night-chain\`（不存在就建）

### 开工（在读方案之前先做完）

1. 读 `night-chain\` 下已有的状态文件，先搞清现在到第几棒了。
2. **等前棒（最关键的一条）**：如果前一棒的 `<N-1>-done.json` 不存在，说明前棒还在跑 ——
   **不要开工，不要碰仓库里的任何文件**。每 60 秒查一次，最多等到本棒的交棒硬线。
   - 等到了 → 正常开工。
   - 等不到 → 写 `<N>-blocked.json`（记录：等了多久、前棒缺什么、你读到了哪些状态文件），
     然后**跳过本棒直接写 `<N>-done.json`（状态写「未执行」）并交棒**，把问题如实留给第 5 棒。
   > **绝对不能和前棒并行改仓库。** 两棒同时改 `sync-content.mjs` / `README.md` / verify 数字会互相踩烂，
   > 而且这种烂很难查 —— 最后没人知道是谁改坏的。
3. 建 `<N>-running.json`：`{ "棒次": N, "任务": "...", "开工": "<ISO>", "计划交棒": "<ISO>" }`
4. **只在预计会超预算时**，才把下一棒的执行时间推到自己预计结束时间 +3 分钟。

### 收尾（交棒前必做，顺序不能反）

1. 按 `00-index.md` 第五节收尾：`npm run verify`（跳过的层要如实列出）→ 四处同步 verify 数字 → README → memory 日志追加。
2. **保证仓库可运行**：`npm run build` 能过，`npm run verify` 至少不能比开工前更红。
   如果做不到，**回滚到开工前的状态**并在报告里说明回滚了什么 —— 留一个坏状态比少做一个功能严重得多。
3. 写 `<N>-done.json`：

```json
{ "棒次": 1, "任务": "图标资产库", "状态": "完成 | 部分完成 | 未执行 | 失败",
  "开工": "2026-09-21T23:05:00+08:00", "收工": "2026-09-22T01:08:00+08:00",
  "verify": { "总数": 473, "分项": { "arch": 35, "graph": 59, "project": 321, "engine": 17, "parity": 12, "archify": 29 }, "跳过": ["parity", "archify"] },
  "做完的": ["具体到文件/阶段/断言编号"],
  "未做完的": ["具体到「哪个阶段 / 哪个文件 / 哪条断言」"],
  "踩的坑": ["..."],
  "给下一棒的话": "..." }
```

> `未做完的` **必须具体到文件、阶段或断言编号**。不许写「部分未完成」「基本完成」这种话 —— 第 5 棒要靠这份清单去核。

4. **交棒**：把下一棒任务的执行时间改成「现在 + 3 分钟」。
   即使「现在 + 3 分钟」已经晚于下一棒的交棒硬线，也照设不误 —— 让下一棒自己去判断还来不来得及。

## 三、五棒共享的铁律（承 `00-index.md` §三，此处只列今晚特别容易踩的）

1. **事实源只能是 `tools/content/*.py`**。改完必跑 `python tools/build-content.py` → `node scripts/sync-content.mjs`。
   锚点/交叉校验失败会中断 —— 那是它在救你，别绕过去。
2. **写 JSON 一律 `newline='\n'`**（生成器里已有 `write_json`，照抄），否则整份文件变「CRLF 假变更」。
3. **verify 数字要同步四处**：`arsenal-profiles/arsenal.json` 的 `verifyChain` / `.verify/project-check.ts` 手写总数 / `README.md` 总数 / `README.md` 分项表。
4. **零外部依赖是硬约束**：运行时依赖只有 `next / react / react-dom`。不许引入图标库、动画库、图表库、滑杆库。
5. **bash 的 PATH 是坏的**：每条命令前必须
   `export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Windows:$PATH"`
   不加则 `ls` / `dirname` / `head` 全部 command not found（那个 shell shim 自己就先报错）。
   已实测有效。
6. **运行时位置**：node `C:\Users\Administrator\.workbuddy\binaries\node\versions\22.22.2-3\node.exe`；
   python `C:\Users\Administrator\.workbuddy\binaries\python\versions\3.13.12\python.exe`；
   JDK17 `C:/Users/Administrator/.jdks/corretto-17.0.12`。
7. **调试产物写 `.workbuddy/_*`，用完即删。**
8. **不许把没做完的说成做完了。** 这一条今晚尤其重要 —— 第 5 棒是专门来核这件事的，
   自述和实际不符会被逐条点名。

## 五、第 5 棒 · 夜跑巡检与补漏

**你是今晚唯一一个不写新功能的人。你的产出是「真相」和「把摊子收拾干净」。**

### 5.1 收集
1. 读 `night-chain\` 下全部状态文件（`0N-running.json` / `0N-done.json` / `0N-blocked.json`）。
2. **第 5 棒不等待**：07:05 无条件启动。如果此时还有工作型任务在跑（`04-done.json` 不存在），
   等到 07:30 为止；还等不到，就按「第 4 棒未交棒」如实记录并继续往下做。
   **绝不要和工作型任务并行改仓库** —— 你只在确认它们全部结束后才动文件。

### 5.2 独立验证（不许只信状态文件）
每一棒的每一项「声称做完的」，都要自己动手验一遍：

| 验什么 | 怎么验 |
|---|---|
| 仓库能不能跑 | `npm run build` + `npm run verify` 真跑一遍，记录真实数字与跳过的层 |
| 文件真的在不在 | 声称新建的文件（`arsenal-icons/icons.json` / `arsenal-cases/` / `com/arsenal/scan/` …）逐个 `ls` |
| 闸门真的在工作 | 故意写坏一处（错 key / 错路径 / 缺字段），确认 `sync-content.mjs` **真的中断**；验完改回来 |
| 断言真的在工作 | 故意构造反例，确认对应的 verify 断言**真的变红**；验完改回来 |
| 页面真的能开 | `/icons` `/cases` 页面对应的 `page.tsx` 存在，且 `Shell.tsx` 的 `NAV` 里有对应项 |
| 数字真的同步 | 实测 verify 总数 vs 四处声明处（`arsenal.json` / `project-check.ts` / README 两处）逐个对齐 |
| memory 真的写了 | 今天的日志文件末尾有今晚的记录 |

> **「反着验一次」是巡检的核心动作。** 一条从没红过的断言，和一个摆设没有区别 ——
> 今晚四棒都很赶，最可能的偷工减料就是「断言写了但其实是假的」。

### 5.3 补漏（只补 07:55 前能补完的）

**优先补（按这个顺序）**：
1. 仓库不可运行 / `npm run build` 挂 → 最高优先级，必须修
2. `npm run verify` 挂红 → 修到绿，或把挂红项如实记录并说明原因
3. verify 数字四处不同步 → 同步
4. memory 日志缺 / README 没更新 → 补上
5. 状态文件缺 → 补齐

**不补**：任何需要 30 分钟以上的新功能开发。宁可如实写「未完成」，也不要开一个必然做不完的头。

**绝对不许**：为了报告好看而修改结论、把「没做」写成「做了」、或者删掉挂红的断言。

### 5.4 产出
1. 写 `D:\workspace\2026\mryang-arsenal\.workbuddy\night-chain\REVIEW.md`，逐棒记：
   - 该棒自述的状态 vs 你独立验证的结果
   - **差异清单**（哪几项它说做了、实际没做 / 做得不对）
   - 你补了什么、还差什么
   - verify 实测数字（总数 + 分项 + 跳过）
2. `night-chain\` 下所有 `_running` / `_blocked` 之类的一次性状态文件清理掉，只留 `0N-done.json` 与 `REVIEW.md`。
3. 报告用 present_files 呈现（`REVIEW.md` 优先）。

### 5.5 07:55 硬停
到 07:55 无论做到哪一步，立刻停止动手，把当前状态写进 `REVIEW.md`。
**08:00 之后每一分钟都在扣积分**，不要为了「再补一点」越线。
