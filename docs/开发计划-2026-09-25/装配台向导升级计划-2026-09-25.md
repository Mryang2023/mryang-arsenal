### P0-2 真正的层级约束：形态决定下游候选

**目标**：① 选的形态真正收窄 ②③④ 能选什么，而不只是预填一组默认值。

**数据侧**（走数据管道，禁止直接改 JSON）：

| 步骤 | 动作 |
|---|---|
| 1 | 在 `tools/content/stack_*.py` 里给维度加 `scopes?: string[]` —— 该维度在哪些**形态**（= `stack_presets.py` 的 preset id）下可选 |
| 2 | 示例：`registry`（服务注册）/ `gateway`（网关）/ `configcenter`（分布式配置）→ `scopes: ['microservice','meso','ha','data']`，**单体与最小集形态下不可选** |
| 3 | 跑 `python tools/build-content.py` → `node scripts/sync-content.mjs` |
| 4 | `StackDimension` 接口加 `scopes?: string[]` |

> ⚠️ **字段必须是可选的**（`scopes?`）。【16】字段契约的规矩：必选字段逐记录核，异构字段必须可选 —— 不是每个维度都有形态限制，写成必选会红。

**UI 侧**：

| 步骤 | 动作 |
|---|---|
| 5 | `wizard.ts` 加两个纯函数：`isDimAvailable(shapeId, dimId)` / `isOptionAvailable(shapeId, dimId, optId)` |
| 6 | ②③④ 里「当前形态不可选」的项 → **灰显 + `title` 说明原因**（如「单体形态不需要服务注册中心」）+ `cursor: not-allowed`，**不隐藏** |
| 7 | 形态切换时：原本灰显的解锁；**已选的项若变不可选 → 结论条提示「N 项与当前形态冲突」并给一键处理**，绝不静默改用户已做的选择 |

**设计约束（关键，别踩）**：
> **约束只能「灰显」，不能「隐藏」。**
> 【17】断言把 33 个槽位和三档宽度分布（3/1/29）钉死了。一旦按形态隐藏槽位，渲染出来的卡片数就变了，分布断言会**静默变红**（不是代码错，是数据驱动的数字变了）。灰显保留槽位 → 断言不动，同时用户仍能看到「这个零件存在，但当前形态不需要它」，比隐藏更诚实。

**验收**：
- 反着验：把某个维度的 `scopes` 故意写错 → 对应项必须真的变灰 / 断言变红，还原后复绿。
- 单体 → 微服务切换后，不可选项数量可数且变化正确。
- `verify:project` 全绿（【17】分布 3/1/29 不动）。

## 5. 验收门禁（挂现有 verify 链，不另起炉灶）

1. **源码即数据**：新增页签 / 视图 / 状态必须同步 `TabId` ↔ `tab === 'x'` 两处；解析前先 `stripComments()`。
2. **改装配台前先 grep `.verify/project-check.ts`** 对 `StackComposer.tsx` 的字符串断言（`stack-bench` / TabId 三处一致 / `onSelect={focusDim}` / `loadSnapshot(` / `loadDrafts` / `hist.record(`≥6 / `目录树 / 架构图 / 隐患单 → 右侧交付预览`）。这些是对**源码文本**断言，抽文件会让断言静默变红。
3. **视觉层现测**：改 UI 先 `node scripts/next-run.mjs build` 再跑视觉层（`out/` 陈旧会红在旧产物上）。
4. **断言反着验**：每条新断言注入一次错误确认真红，还原复绿；还原用 `git checkout --` 或 `newline=''`（防 CRLF 污染）。
5. **数据字段**：新增属性一律 `tools/content/*.py` → `build-content.py` → `sync-content.mjs`，禁止直接改 JSON。
6. **口径同步**：增删断言同步四处 —— 档案 `verifyChain[*].count`、README 总数句、README 分项表、重跑 `sync-content.mjs`。
7. **localStorage 键**：新增键必须有读取方，否则不加。
