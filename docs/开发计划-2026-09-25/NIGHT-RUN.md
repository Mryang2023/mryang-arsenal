## 三、一棒三段（缺一不可）

**一棒 = 开发 → 自检补漏 → Code Review。**
这不是「可选的最后两步」，这是**交付的定义** —— 没跑过自检和 review 的产出，不算这一棒做完了。

| 段 | 对准 | 回答什么 |
|---|---|---|
| 开发 | 方案的实施计划 | 该做的做出来了吗？ |
| **自检补漏** | **方案**（要求） | 该做的都做了吗？有没有静默失败？ |
| **Code Review** | **代码**（实现） | 写得住吗？有隐患吗？和项目一致吗？ |

收尾另算（约 20 分钟），见 §四。

### 3.1 开发

- **开工先砍范围**，砍到开发预算内。方案原文按「一整晚」写，砍是正常操作，不是偷懒。
  砍完写进 `<N>-running.json`，收工时对照它交账。
- 前置依赖缺失 → **降级 + 如实记录，不许硬造**。
- 阶段化推进，每阶段做完立刻验收。

### 3.2 自检补漏（完整性）

**目标：找出「看起来完成、实际没完成」的地方。** 必做五件事：

1. **验收对照** —— 把方案的「分阶段实施 / 验收标准」逐条拉成表，标 ✅ / ⚠️部分 / ❌未做。
   **对照的是方案原文，不是自己的印象。**
2. **存在性核验** —— 声称新建的文件，`ls` / `grep` 逐个确认真的在。
3. **反着验 ≥2 处** —— 挑本次新写的闸门或断言，**故意注入错误**，确认真会红，然后还原。
   > 一条从没红过的断言，和摆设没有区别。
   > ⚠️ **注入后必须先断言「注入真的打中了」**（本仓库踩过两次：删错层级、字段名写成 `exclusiveGroups` 而非 `conflicts`，结果注入打空、检查仍绿，差点误判成「检查失效」）。
4. **静默失败排查** —— 找「断言通过但样本量为 0」的检查（空跑通过）。必须点名。
5. **引用核实** —— 方案里引用的 id / 路径 / 依赖，去仓库核实真实存在。
   > 本仓库踩过：方案示例里的规则 id 是编的，照抄就错。

未完成项**先补**；补不完的写进清单，具体到文件 / 阶段 / 断言编号。

### 3.3 Code Review（质量）

审**本次改动的代码**（不审全仓），五个维度：

| 维度 | 查什么 |
|---|---|
| 正确性 | 边界值、空值、并发、错误路径、类型、异步时序 |
| 安全 | 注入、路径逃逸、敏感信息硬编码、权限、对外部输入的信任 |
| 性能 | 循环内 IO、N+1、无界集合、重复计算、不必要的同步 |
| 可维护性 | 重复代码、魔法数、命名、死代码、**残留调试代码** |
| 一致性 | 与项目既有范式 / 类型体系是否一致；有没有留下「功能等价但形态不同」的平行通道 |

每条按 `[P0/P1/P2] file:line —— 问题 → 根因 → 处置` 记录。
**P0 与便宜的 P1 当场修**，修完重跑验证；其余进清单并写明为什么没修。
不许把 P2 包装成 P1 凑数，也不许漏报。

### 3.4 段间门禁

| 关卡 | 规则 |
|---|---|
| 开发 → 自检 | 代码能编译 / 能构建通过 |
| 自检 → Review | 无未修的 P0 完整性缺陷 |
| Review → 收尾 | 无未修的 P0 代码缺陷 |

> **不许带着已知的重病往下走。** 轻问题可以记账前行，重问题不行。

## 五、终检棒

**唯一不写新功能的一棒。产出是「真相」+ 把摊子收拾干净。**

1. **等（但绝不并行）** —— 第 3 棒没交棒就等到 07:05，等待期间不碰任何文件。
2. **收集** —— 读状态目录全部文件与各棒报告。
3. **独立验证（核心动作，不许只信状态文件）**：
   全量构建 + 全量九层真跑一遍；声称新建的文件逐个确认；
   **闸门/断言故意写坏一次，确认真会红**（优先验**从未红过**的）；
   页面真挂上；数字真同步；memory 真写了；**git 真提交了、工作区干净**。
4. **归因核查（本晚第一优先）** —— 用 `git show --stat <hash>` 逐棒核对「提交的文件范围 vs 该棒授权范围」，

   **不补**需要 30 分钟以上的新功能。
   **绝对不许**为了让报告好看而改结论、把「没做」写成「做了」、删掉挂红的断言。
6. **产出 `REVIEW.md`** —— 逐棒记「自述 vs 独立验证」+ **差异清单（逐条点名）** +
   补了什么 + 剩余工作量（**按离闭环的距离**排 P0/P1/P2，这份是下一晚的输入）。
   清理一次性状态文件，只留 `0N-done.json` 与 `REVIEW.md`。用 present_files 呈现。
7. **硬停 07:55** —— 到点无条件停止动手。窗口外每分钟都在扣积分。
