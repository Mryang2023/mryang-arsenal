## 第一棒干了什么（修了 6 个「导出即坏」根因 + 4 个连带缺陷）

冒烟先後抓出 6 个此前所有绿灯都没发现的启动根因：

1. mysql JDBC URL 里嵌着字面引号（Python 续行写法残渣），且 `characterEncoding=utf8mb4` 不是合法 Java 编码名——建连即炸；
2. 数据源没有 username/password；全库 11 处环境变量占位符无默认值——选了 Redis/RabbitMQ/Nacos 而没设对应环境变量的，启动直接解析失败；
3. 各选项的 yml 块拼进主配置后产生顶层 `spring:` 重复键——Spring Boot 的 YAML 加载器固定拒绝重复键；
4. `observability=prometheus` 缺 `spring-boot-starter-aop`——TimedAspect 启动即 NoClassDefFoundError；
5. logback 只认 dev/prod 两个 profile——**默认启动一个日志 appender 都没有**，应用静音到死，排障无从下手（这直接拖慢了本次排障）；
6. `migration=none` 的 schema.sql 放在默认不被执行的位置且 DDL 不幂等。

连带修复：`auth=custom` 组合的测试编译不过（测试无条件 import 不存在的 AuthInterceptor）、secret:file 默认项往主 yml 埋 `${DB_PWD}` 地雷、案例库新主线样例代码违反自家 MUST/NEVER 闸门（白天 0501af5 带入、generated 产物过期掩盖）、档案与 README 的项数口径漂移。

verify:project 新增【16】启动前提自检 8 条，把「能启动」从口号变成机器断言。
