2. **等前棒（最关键的一条）**：`<N-1>-done.json` 不存在 → **不许开工，不许碰仓库任何文件**，

## 三、一棒三段（缺一不可）

**一棒 = 开发 → 自检补漏 → Code Review。**
这不是"可选的最后两步"，这是**交付的定义** —— 没跑过自检和 review 的产出，不算这一棒做完了。

| 段 | 预算 | 对准 | 回答什么 |
|---|---|---|---|
| 开发 | 60% | 方案的实施计划 | 该做的做出来了吗？ |
| 自检补漏 | 20% | **方案**（要求） | 该做的都做了吗？有没有静默失败？ |
| Code Review | 20% | **代码**（实现） | 写得住吗？有隐患吗？和项目一致吗？ |

收尾另算（约 20 分钟），见 §四。

### 3.1 开发

- **开工先砍范围**，砍到开发预算内。方案原文按"一整晚"写，砍是正常操作，不是偷懒。
  砍完写进 `<N>-running.json`，收工时对照它交账。
- 前置依赖缺失 → **降级 + 如实记录，不许硬造**。
- 阶段化推进，每阶段做完立刻验收。

### 3.2 自检补漏（完整性）

**目标：找出"看起来完成、实际没完成"的地方。** 必做五件事：

1. **验收对照** —— 把方案的「分阶段实施 / 验收标准」逐条拉成表，标 ✅ / ⚠️部分 / ❌未做。
   **对照的是方案原文，不是自己的印象。**
2. **存在性核验** —— 声称新建的文件，`ls` / `grep` 逐个确认真的在。
3. **反着验 ≥2 处** —— 挑本次新写的闸门或断言，**故意注入错误**，确认真会红，然后还原。
   > 一条从没红过的断言，和摆设没有区别。
4. **静默失败排查** —— 找"空跑通过"的检查（断言通过但样本量为 0）。必须点名。
   > 本夜的三个高发点：① 体检覆盖率的分母写成 0 时显示如何 ② 检查项规则为空时校验器是否"全过"
   > ③ 快照列表为空时是否也显示「无历史」而不是什么都不渲染。
5. **引用核实** —— 方案里引用的 id / 路径 / 依赖，**去仓库里查是否真实存在**。
   > 本仓踩过：方案示例里的规则 id 根本不存在，照抄就错。
   > 本夜特别注意：69 条规则的分母从 `arsenal-rules/meta.json` 读，108/47 从 `arsenal-scan/scan_rules.json` 读，
   > **都不许写死**。

未完成项**先补**；补不完的写进清单，具体到文件 / 阶段 / 断言编号。

### 3.3 Code Review（质量）

审**本次改动的代码**（不审全仓），五个维度：

| 维度 | 查什么 |
|---|---|
| 正确性 | 边界值、空值、并发、错误路径、类型、异步时序 |
| 安全 | 注入、路径逃逸、敏感信息硬编码、权限、对外部输入的信任 |
| 性能 | 循环内 IO、N+1、无界集合、重复计算、不必要的同步 |
| 可维护性 | 重复代码、魔法数、命名、死代码、**残留调试代码** |
| 一致性 | 与项目既有范式 / 类型体系是否一致；有没有留下"功能等价但形态不同"的平行通道 |

每条按 `[P0/P1/P2] file:line —— 问题 → 根因 → 处置` 记录。
**P0 与便宜的 P1 当场修**，修完重跑验证；其余进清单并写明为什么没修。
不许把 P2 包装成 P1 凑数，也不许漏报。

**本夜专项审查**：`SourceResolver.fromPath` 接受任意本地路径 —— 解剖台的「本地目录」输入
不得路径逃逸、不得静默解析到别处、不得把扫到的绝对路径当敏感信息存进快照。

### 3.4 段间门禁

| 关卡 | 规则 |
|---|---|
| 开发 → 自检 | 代码能编译 / 能构建通过 |
| 自检 → Review | 无未修的 P0 完整性缺陷 |
| Review → 收尾 | 无未修的 P0 代码缺陷 |

> **不许带着已知的重病往下走。** 轻问题可以记账前行，重问题不行。

1. **跑全量验证** —— 不是只跑自己改的那一层。**没跑过就不能说它是绿的。**
   `cd arsenal-web && npm run verify`；跳过的层必须如实记下（`report.ts` 的 `knowinglySkipped()` 目前 2 项）。
2. **同步所有派生数字**（见 §六），改完复跑一次确认生效。
3. **git commit** —— 本棒产出必须在收工前形成一次提交，message 用 `feat(scope): ...` 格式。
   > 一夜不提交 = 没有版本快照，中途改坏了无法回滚到棒间状态。
4. **清理调试产物** —— `_*` 前缀的临时脚本 / 备份 / 日志全删。
5. **README / memory 日志** —— 追加本棒记录到 `.workbuddy/memory/2026-10-11.md`。
6. **回滚判断** —— 构建或验证比开工前更红且修不了 → **回滚到开工前状态**并在报告里说明。
   留一个坏状态比少做一个功能严重得多。
7. **写 `<N>-done.json`** —— 必含 `开发` / `自检` / `review` / `验证` / `数字同步` / `提交` / `清理` 七组字段。
   `开发.未做完的` 不许写"部分未完成"，必须具体到**文件 / 阶段 / 断言编号**，能被一条命令核对。

**唯一不写新功能的一棒。产出是「真相」+ 把摊子收拾干净。**

1. **等（但绝不并行）** —— 最后一棒没交棒就等到 07:40，等待期间不碰任何文件。
2. **收集** —— 读状态目录全部文件（`0N-running` / `0N-done` / `0N-blocked`）与各棒报告。
3. **独立验证（核心动作，不许只信状态文件）**：
   全量构建 + 全量验证真跑；声称新建的文件逐个确认；
   **闸门/断言故意写坏一次，确认真会红**（优先验从未红过的）；
   页面真挂上导航；派生数字真同步；memory 真写了；**git 真提交了、工作区干净**。

   用 `present_files` 呈现。

## 六、项目铁律（**违反即事故**）

1. **事实源只能改 `tools\content\*.py`**。改完必跑
   `python tools\build-content.py` → `node arsenal-web\scripts\sync-content.mjs`。
   **本夜棒 1/3 不碰数据层；棒 2 新建 `arsenal-checkups/` 是手写事实源，同章程层 `arsenal-charter/` 的性质
   （不进生成器，别人要用不必装军火库）。**
2. **写 JSON 一律 `newline='\n'`**。
3. **零外部依赖**：不许引入任何图标/动画/图表/滑杆/绘图库。
4. **加/改 verify 层要改六处六件套**：`package.json` / `verify-all.mjs` 的 `LAYERS` /
   `report.ts` 的 `LAYER_NAMES` / `meta.ts` 的 `CHAIN_ORDER` / `arsenal.json#project.verifyChain` /
   README 两处（分项表 + 正文）。**漏一处必事故。**
5. **新 verify 层必须用独立 key** —— `finish(layer)` 用 layer 字符串同时决定状态文件名与查表层名，
   两个脚本共用一个 key 时**后写的覆盖先写的**，先跑的项数被静默吞掉。
6. **层数不许写死**（「十二层合计」这种字面量会在加层那天过期）。从 `arsenal.json` 的
   `verifyChain.length` 算，`finish()` 各自比一次、链尾 `verify:meta` 再比一次。
7. **新事实源目录必须登记**：`sync-content.mjs` + resolver + `verify:project` + README 树。
   ⚠️ **`verify:project` 不验本仓README**（它验的是导出包 README）→ 本仓 README 与
   `arsenal.json#project.dirs` 漏登记**永远不会红**。章程目录就漏过，现在由【13】守着。**新建目录照抄这条。**
8. **断言反着验**：注入 → 红 → 还原 → 绿。还原用 `cp` 不用 `git checkout --`（后者会抹掉未提交改动）。
9. **git 逐文件**：`git add <文件>` + `git commit -- <路径>`，提交前核对 `git diff --cached --stat`；
   **目录级 pathspec 会夹带 `_*`**。误提交：`git reset --soft HEAD~1` + `git reset HEAD -- <路径>`。
10. **同一文件多处改动必须串行**（并行 Edit 静默丢改，tsc 仍 0 错）。
11. **不许 push**（本机 PortableGit push 假死），只 commit。
12. **动态路由绝不写 `dynamicParams=false`**（dev 报缺 `generateStaticParams`）；404 由页面内 `notFound()` 兜。
13. **不许把没做完的说成做完了**。自检段与终检棒专门核这条。

## 七、本仓雷区（解剖台专项 + 通用）

**专项（本三夜必读）**：
- **`SourceResolver.fromPath` 接受任意本地路径** —— 解剖台是「用户给一个路径让服务器去读」的接口，
  本仓此前没有这个形态。安全审查必做：路径逃逸、符号链接、静默解析到别处、把绝对路径当敏感信息存进快照。
- **不要重写 `ArchifyLab.tsx` 的出图链路**（765 行成品）—— 棒 1 只做「抽数据层 + 加壳」，
  改完必须回归 `/archify` 页面。
- **`nav-active.ts` 与 `Shell.tsx` 的 `NAV` 有源码文本断言** —— 新增导航项可能让某条断言的数字对不上，
  动之前先 grep `verify:project`（`.verify/project-check.ts`）对该文件的字符串断言。
- **体检覆盖率的分母从 `arsenal-rules/meta.json` 读**，映射数从 `arsenal-scan/scan_rules.json` 读
  （当前 69 / 108+47）。**写死 = 过期那天静默撒谎。**
- **「未覆盖 27 条」必须显示** —— AST 层覆盖 42/69，「没检查」和「检查通过」在页面上长得一模一样
  （2026-10-04 `charterNotExecutableCount` 漏 `PJX-` 前缀，显示 34 而章程只有 2 条）。
- **观察项必须数据化** —— 写进 Java 就意味着换语言得改代码重编译。方案 2 阶段 A 已写明。
- **快照目录必须进 `.gitignore`** —— 本仓已有规矩：别的项目的资料不该进军火库
  （`profile-store.ts` 顶部注释）。漏了这步会把别人的源码路径提交进来。

**通用（历夜实测沉淀）**：

  已知受害者：`verify:archify` 调外部 CLI 恒失败 3 项。**看到 Archify 红先验 EBUSY，别改代码。**

  node 用 managed 22.22.2。
- Git Bash 下 `npm run` exit 1 → 用 node 直跑 npm-cli.js 或脚本本体。
- **safe-delete ≥50 文件会拦，且后台任务无法弹批准**（stdout 全空，只有一行 stderr）。

- spawn node 必须传原生 Windows 路径（`C:\...`）；`/d/...` MSYS 风格只有 spawn bash 能用。
- curl 读不了 /tmp；给 node/python 用 Windows 路径。
- `GlobalExceptionHandler` 把 404/405/415 吃成 500 —— 新接口入参校验在 Controller 里做，别依赖框架异常。
