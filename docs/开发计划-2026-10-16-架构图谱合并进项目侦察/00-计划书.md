# 架构图谱 × 项目侦察合并 · 计划书

**日期**：2026-10-16
**代号**：`/arch → /autopsy` 合并
**一句话**：把「架构图谱」的六视图与可拖拽技术画布整体并入「项目侦察」—— 一次扫描出全套项目画像；`/arch` 路由退役为重定向页，全仓只留一个「给地址 → 出全景」的入口。

---

## 0. 先说结论：你的两个判断，一个要修正，一个完全成立

### 0.1 「架构图谱生成的架构图比较真实」—— 数据是同一条，差别全在呈现层

调研完发现两条链路**早就共用同一个模型**，没有两套生成逻辑：

| | `/arch` 技术架构（你觉得好的） | `/autopsy` 技术栈部署图（你觉得不对的） |
|---|---|---|
| 模型 | `buildTechArch(picks, edits, {topology})` | `buildTechArchFromFacts(facts)` = **同一个** `buildTechArch` + 副本事实覆盖 |
| 选型来源 | localStorage 里的装配台快照 | 扫描（`factsToPicks`） |
| 副本徽章 | **没有**（不读部署清单） | **有**（K8s `replicas` / Helm `replicaCount` 覆盖到应用节点，读不到就不画、不兜底 1） |
| 交互 | 拖拽 / 改名 / 集群形态 / 加节点 / 加连线 / 五套主题 / 复制 PNG / 下载 SVG / 技术说明书 Markdown / 交给 Archify 出 HTML | 一张静态 SVG，只能整图下载 |
| 渲染 | `hooks: true` + 指针事件 + 编辑态持久化 | `dangerouslySetInnerHTML` 原图，无钩子 |

**所以「照搬过去」的正确含义是：把 `TechArch` 组件（858 行，交互全在里面）搬进解剖台，喂扫描出的选型 —— 不是重画一张图。** 重画 = 第二份实现，本仓铁律不允许。

同时有一个**反向缺口**必须补：`/arch` 的画布不读扫描的副本事实，而解剖台现在的静态图有。合并时若只搬组件不搬事实，会把「图上写几节点就是几节点，每条可追溯到部署清单」这条现有纪律弄丢 —— 那是倒退，不是合并。

### 0.2 「架构图谱的内容可以并进项目侦察」—— 完全成立，而且机器已经存在

`src/lib/profile-draft.ts` 的 `buildProfileDraftFromFacts()` 早就把一份扫描变成**六视图档案草稿**：扫描读到的填进去，读不到的（业务定位、消费方、非目标、路线图）留 `TODO` 并逐条列出。`/arch` 的「从代码生成」入口用的就是它。

**缺的只是三件事**：① 草稿没接进解剖台；② 可拖拽画布没进解剖台；③ 两页各有一个扫描入口（`ProfilePicker` 一个、`AutopsyLab` 一个），是漂移温床。

### 0.3 三个必须躲开的坑（共同点：都不报错，只会静静地错）

| # | 坑 | 不躲的后果 |
|---|---|---|
| 坑 1 | **编辑态单键串项目**：画布的拖拽坐标 / 自定义节点存在单个 localStorage key `arsenal-tech-arch-edits-v1` | 扫 A 项目拖好的布局，原样出现在 B 项目的图上。两个页面共用时是特性，扫描场景下是事故 |
| 坑 2 | **IR 两份实现**：`buildAutopsy()` 已经算好 `ir / issues / shape`，但解剖台七个面板**一个都不消费**（只有 `/archify` 的 CodeIntake 用）；`TechArch` 又自己从 picks 重建一份 | 同一个项目两个 IR，早晚分家，而两边都全绿 |
| 坑 3 | **手写档案比扫描草稿富**：内置档案 `arsenal-profiles/arsenal.json` 是手写的；扫描草稿的业务视图大半是 TODO | 合并后没扫描就扫一遍空页面，或把草稿当成品卖 |

## 1. 目标形态

输入区与七个页签不动，只改造「架构面板」；`/arch` 变重定向页。

```
/autopsy 项目侦察（合并后）
├── 输入区（不变）：本地目录 / https git / zip → 一键分析
├── 页签
│   ├── 架构面板（改造）
│   │   ├── 档案条：内置「杨先生的军火库」▣ ｜ 导入档案 ⇪ ｜ 本次扫描草稿 ✦（扫描后才出现）
│   │   ├── 子页签 ① 技术架构 —— TechArch 可拖拽画布
│   │   │      picks 来自本次扫描；副本数来自部署清单；编辑态按项目隔离
│   │   ├── 子页签 ② 应用分层 —— 现有分层图（零改动）
│   │   └── 子页签 ③ 六视图 —— 业务 / 数据 / 应用 / 产品 / 项目 五张静态图
│   │          数据来自「当前档案」；草稿模式亮成熟度：N 条来自扫描 · M 条待你补
│   ├── 服务拓扑 / 体检报告 / 历史 / 生命体征 / 活体对账 / 功能视图（全部不动）
├── /arch → 重定向页（meta refresh + 一句话说明，照 /charter → /standards 先例）
```

**没扫描时页面讲什么**：档案条默认落在内置档案，六视图离线可看（构建期快照，不依赖后端）；技术架构画布跟随装配台选型快照（现有 `/arch` 行为），顶部横幅说清「这张图现在不是扫描结果」。**扫描后**：档案条多出「本次扫描草稿」，选中它六视图切草稿、画布切扫描选型。

## 2. 关键技术决策（5 条，每条带理由）

| # | 决策 | 理由 |
|---|---|---|
| **D1** | **搬组件，不重画**。`TechArch` 加三个可选 props：`titleRoot`（标题用项目根名，默认仍是 `projectDoc.artifactId`）、`banner`（顶部说明注入，默认现有「跟随装配台」文案）、`irOverride`（`{ir, issues, name}` 注入，默认自己从 picks 重建）。默认值全部维持现状 → `/arch` 行为字节级不变 | 858 行交互（拖拽 / 图标库 / 连线 / 主题 / PNG / Markdown / Archify 通道）是现成的；`project-check` S2-7 还钉着「`<TechArch` 不许回装配台 composer」——搬进 autopsy 不触发它，但动手前仍要 grep 一遍 |
| **D2** | **扫描事实经拓扑层进画布，不在画布里加分支**：`picks = factsToPicks(facts).picks`；副本数 `replicaFact(facts)` 有值 → `withParam(emptyMeta(), 'replicas', fact.replicas)`，无值 → `emptyMeta()`；然后照旧 `nodeTopologyMap(picks, meta)` | `effectiveAppReplicas` 的「滑杆覆盖」通道就是干这个的；`paramIsSet` 语义保证「未设」≠ 1，不兜底是既有纪律；`applyReplicaFacts` 那套「只覆盖应用卡」的规矩因此自动继承 |
| **D3** | **编辑态按项目分键**：`picksProp` 传入时 key = `arsenal-tech-arch-edits-v1:<facts.root>`；不传（`/arch` 快照路径）维持单键现状 | 装配台 ↔ 图谱的「选型改图跟改」不受影响；扫描场景按项目隔离。反着验：扫 A 拖好 → 扫 B → B 必须是自动布局 |
| **D4** | **六视图渲染器零改动**：`buildProfileDraftFromFacts(facts) → resolveProfile(draft, buildMetrics()) → composeArchViews → diagrams.tsx`；草稿的 `TODO ` 前缀原文上图，容器顶部出成熟度条 | 渲染器本来就不认军火库（`project-check` ⑥ 钉着「只许引类型」）；草稿不当成品卖，`TODO` 前缀本身就是标记，不需要第二套标记体系 |
| **D5** | **`/arch` 退役为重定向页**，进 `project-check` 的 `ORPHAN_OK` 白名单；导航删入口；`StackDeck` 两处 `/arch` 链接改指 `/autopsy` | `/charter → /standards` 是同型先例（迁移页保旧书签）；重定向页仍是页面 → `shoot.mjs` 的 fixedPages/urls/shots 三个数字不变，视觉层风险最低。顺带修一个现存错链接：`StackDeck.tsx:692` 文字说「未识别依赖明细在六大架构页」，实际在解剖台第四区 |

## 3. 分棒计划（4 棒）

依赖：`棒1 → 棒2 → 棒3 → 棒4`。每棒独立可验收、可回滚。

### 棒 1 · P0 · 画布进台：技术架构可拖拽

**做什么**

1. `TechArch.tsx` 加三个可选 props（D1），默认值维持现状。
2. `AutopsyLab` 架构面板拆子页签（技术架构 / 应用分层 / 六视图）；技术架构子页签渲染
   `<TechArch picks={artifacts.picksRes.picks} meta={scanMeta} titleRoot={artifacts.facts.root} banner={…} irOverride={artifacts.ir} />`。
3. `scanMeta`：`replicaFact(facts)` 有值才 `withParam`（D2）。
4. 编辑态按 `facts.root` 分键（D3）。
5. **IR 二义收口**（坑 2）：画布的「交给通用绘图器」区在 `irOverride` 传入时直接用 `artifacts.ir / issues`（facts 版，带副本事实、带 theme→preset 绑定），不再自己从 picks 重建；`/arch` 路径行为不变。
6. `ArchPanel` 撤下「技术栈部署图」卡片（下载职能由画布工具栏承担），保留「应用分层图」卡片与 notes 清单。
7. 主题二合一：外层主题选择器只服务分层图；画布主题走画布自带五套（画布主题同时决定 Archify preset，本来就该它自己管）。

**复用清单**（不新建）：`arch-canvas.ts`（1216 行画布引擎）、`TechArch.tsx`、`topology.ts`（`withParam` / `nodeTopologyMap` / `effectiveAppReplicas`）、`facts-arch.ts`（`factsToPicks` / `replicaFact`）。

**验收**

- 扫军火库自身：画布出图、节点可拖、选中可改名、下载 SVG 与画面一致；
- 副本事实：fixture 里有 K8s `replicas` 声明的，应用卡徽章数与声明一致；没有声明的不画徽章（不出现「×1」）；
- **反着验**：扫 A 拖出布局 → 扫 B → B 的画布是自动布局（编辑不串）；
- 后端不在时：画布不新增离线依赖，`probeArchify` 失败只灰「直接生成 HTML」按钮（既有行为）。

**要同步的断言**：grep `project-check` 对 `TechArch` 的源码文本断言（S2-7 与 STACK_9PX 清单）；`graph-check` 的 hooks 几何断言不受新增 props 影响（默认路径不变）。

### 棒 2 · P0 · 六视图进台

**做什么**

1. 档案条进架构面板：内置（`PROFILE_SUMMARIES`）+ 导入（`profile-store.ts`）+ 「本次扫描草稿」（扫描后出现）。
2. `ProfilePicker` 搬进来时**删掉它的扫描段与 `CodeIntake` 引用** —— 全仓扫描入口只留 `AutopsyLab` 一处（现状是两个，漂移温床）。`CodeIntake` 本身不动（`/archify` 的「从代码生成」继续用）。
3. 六视图子页签：五张图从 `composeArchViews(resolveProfile(当前档案, buildMetrics()))` 取数；当前档案 = 有扫描且选中草稿 ? 草稿 : 选中档案。
4. 成熟度条：「**N 条来自扫描 · M 条待你补**」+ `draft.todos` 可展开列表（每条带档案内位置，如 `views.business.outlets[0]`）。`draft.issues` 非空 → 明确报错不渲染半张图。
5. 封面插画 / 动效原样搬：`VIEW_IMG`（`public/arch/*.webp` 六张不挪位）、`motion.tsx`、`arch-motion.ts`。
6. `diagrams.tsx` / `motion.tsx` / `profile-store.ts` 从 `app/arch/` 挪到 `app/autopsy/`（或提升到 `components/`）—— 搬完必须改 `project-check` ⑤⑦⑧ 的源码文本断言指向（硬约定 6）。

**验收**：没扫描 → 六视图讲内置档案（离线可看）；扫一个陌生项目 → 切草稿，业务视图大片 TODO 但计数诚实、可展开；导入一份 JSON → 六视图切过去；形状坏的档案在按下「选这个」那一刻就被拒（不白屏）。

**三条提前说清的短板**

1. **扫描草稿永远替代不了手写档案**。业务定位、消费方、非目标这些话代码里没有，扫不出来。合并后「项目画像」的完整度取决于你补不补 TODO —— 平台只保证「补的地方亮出来、没补的不装成补了」。
2. **可拖拽画布改的是呈现，不是事实**。拖动、改名、加节点只影响交付物；选型判定仍归扫描与装配台。这条分工在合并后的页面上要原样写着，否则下一个用户会以为拖一下图就改了他的架构。
3. **`/arch` 退役后想恢复，成本 = 把重定向页改回画廊**。六视图渲染器在 autopsy 里是共享组件，不绑死路由；但若选 B 方案（保留画廊），两个 URL 长期讲同一套六视图，漂移温床还在 —— 所以推荐 A。
