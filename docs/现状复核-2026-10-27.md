## 三、0922 之后新发现的（那份报告无从预见）

1. **扫描层 3 条红的根因是「降版混用」，不是「缺构件」**（BLOCKERS B-7 已按此更正）。
   本机 `.m2` 缺 `spring-boot-{health, micrometer-observation}:4.1.1`，而 `spring-boot-{actuator, actuator-autoconfigure}`
   只有 3.3.6、`spring-{jcl, tx}` 只有 6.1.6、`micrometer-core` 只有 1.13.8 ——
   `RuntimeClasspath.findJar()` 会**静默退到本地最高版本**，于是 3.3.6 的 `OnAvailableEndpointCondition`
   被 4.1.1 的 autoconfigure 处理时炸出 `EndpointCondition must be used on @Bean methods…`。
   2026-10-27 r9 起，降版构件会如实进 `missingDeps` 与 `reason`（判定条件与项数未动，3 条红仍是红）。
2. **`_rtcp.sh` 的 `_rt_add()` 同样静默跳过缺件**（r10 起把清单说到 stderr）。它的注释原本写着
   「缺了……不在这里静默跳过」——那是描述 fixture 那一路，而这台跑探针的 JVM 自己的类路径恰恰就在跳过。
3. **探针在 Windows 上一直吐 GBK 字节的 JSON**（r9 修）。JDK 18+ 里 `-Dfile.encoding` 不再决定 `System.out`
   的字符集，它跟随控制台码页；前端 `spawnSync(encoding:'utf8')` 解出来 `reason` / `missingDeps` 全是乱码。
   修法与 `archify-probe.sh` 等三个脚本同款：补 `-Dsun.stdout.encoding=UTF-8 -Dsun.stderr.encoding=UTF-8`。
4. **后端不需要 maven 就能真跑**（推翻 B-4 的前提）：`SKIP_COMPILE=1 bash arsenal-server/scripts/run.sh`
   用 `target/classes` + `.m2` 直起 java，本机 3.6s 起来。一致性层与体检端到端那 12 项「后端类未执行」
   现已可由 `cd arsenal-web && npm run verify:with-backend` 一键变成真跑（实测 `parity 16/16`、`checkup 99/99`）。
