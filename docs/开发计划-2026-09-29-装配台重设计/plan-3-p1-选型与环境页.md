## 一 范围

### 1. 选型台 `/stack`（P1-5 病灶的正面解决）

- **③ 主题框架 19 维分区左导航**：按 `THEME_SECTIONS`（组→维度）生成左栏锚点导航，点击滚动定位；数据全部来自 wizard.ts，**不另立分组表**。
- **已选计数角标**：每个分区（及 JourneyBar 节点）显示「已选/总数」角标；数字**必须从 picks 实时计算**（类似 `flowFilled` 的既有范式），不许手写常数。
- **必缺件点名条**：必选维度缺失时顶部点名（沿用既有 gap 检测的数据源），每条可点击 → **跨页直达归属页**（用 `stepOfDim` → `SECTION_ROUTE` 路由跳转，不新造归属判定）。
- **④ 分层装配保持只读校核台**：`SlotBlock` 无修改入口是故意的，别破坏。

### 2. 环境与模块页 `/stack/env`

- **连接三态卡**：演示模式（H2 内存库零依赖）/ 本机默认（占位符）/ 远端自填 三张卡，当前态高亮；切换不丢已填内容。
- **「密码默认不落盘」提示前置**：从 ⑥ 表单深处提到三态卡旁。
- 模块勾选冲突标黄 + 修复建议保持既有逻辑不动。

## 二 红线

- 归属判定只有 `stepOfDim` 一处；跨页跳转只消费它，不复制一份映射。
- 角标/点名条的数据源是 picks + 事实源维度，禁止在组件里硬编码「19」「33」这类数字（【17】断言守着 33 槽位分布 3/1/29，动了必红）。
- 动手前 `grep -n "THEME_SECTIONS\|focusDim\|stack-bench" arsenal-web/.verify/project-check.ts` 盘点断言；改到的组件同步断言指向。
- 同文件多处改动必须串行；语义色只用 TONE 五色。

## 三 验收标准

1. 左导航 19 维可定位；角标数字与实选一致（选一个 +1，反着验）。
2. 必缺件点名条：故意取消一个必选 → 点名条出现且点击跳对页；补回 → 消失。
3. 三态卡切换后已填的远端连接信息不丢；密码输入默认不落盘提示可见。
4. 全量 verify 十层绿 + 五处数字同步（若断言数变化）+ git 分批提交。

## 四 MVP 与可裁剪

- **必保**：分区左导航 + 角标 + 点名条 + 三态卡。
- **可砍**：校核台视觉美化、过渡动画、角标的批量展开交互。
