## 0. 结论速览（给决策者）

| 问题 | 结论 |
|---|---|
| 要不要引图表库（d3 / recharts / visx / echarts） | **不推荐**。项目已有三套成熟的手写 SVG 渲染器 + 一套字符度量 + 一套内嵌动效，覆盖本次全部图形需求；且 `output:'export'` 纯静态 + 「零绘图依赖」是项目明文立场（README：src/lib 都"不引绘图库"） |
| 现有能力能覆盖多少新 UI | 约 **70%**。字符度量、调色板、语义色、动效、切片卡、代码块、拖拽/点亮/聚焦交互框架、ZIP 导出、prompt 导出全部现成 |
| 真正要从零写的 | 参数-切片命中矩阵、案例对比维度、cookbook 的分层流程图数据适配、场景切换器/看板视图这四块 |
| 最大的坑 | 不是图形，是**校验链**：视觉断言层（A5 对比度）+ `out/` 新鲜度闸门 + `shoot.mjs` 里写死的 `EXPECTED{fixedPages:10, urls:15, shots:45}` |
| 顺手挖到的现存缺陷 | `/cases` 切到 4 个场景会**运行时崩溃**（`kase.benchmark` 无守卫，6 个场景里 4 个没有该字段）；`symptoms` / `intent` / `domain` 三个字段**数据里有、UI 里完全没消费** |

关键点：
- **`/cases` 的数据是构建期打进 bundle 的**（`import raw from '@/generated/cases.json'`），不是接口请求。6 个场景 × 8 切片 × 全量 Java 代码 = `cases.json` **382 KB**，全部进静态产物。

### 1.2 现有交互能力清单

**`/blueprints`（列表页）**
- 有：点击整卡跳转详情；hover 时标题变黄铜色、卡片 `panel-hover`；数据流条（`flow.map` + `layerTheme` 色签）
- 缺：**排序 / 筛选 / 搜索 / 标签过滤 / 对比** 全部没有；4 条案例只能顺序读

**`/blueprints/[id]`（详情页）**
- 有：按层分组的文件切换器（`layerGroups`）；`CodeWithNotes` 的要点角标 ↔ 解读双向 hover 联动；矩阵表；性能表；关联规则跳转 `/rules/{id}`
- 缺：流程图是**纯文字 `<ol>` + 竖线**，不是图；代码文件之间**没有依赖/调用关系可视化**；`matrix` / `performance` 两张表是原始 `string[][]`，**没有图形化**（无条形/热力）；无目录锚点、无进度、无"这一层我看了几个文件"

**`/cases`（CaseLab）**
- 有：场景切换（左侧列表）；驱动参数段选器（整条轨道等宽分割，`aria-pressed`）；参数→方案**纯函数实时重算**（`useMemo`，零请求）；矛盾告警黄条；命中/未命中折叠（未命中带可核对原因）；建议架构 SVG（随参数变节点）；决策清单；切片展开/收起/全展开；单文件下载 `.java`；导出整包 `.zip`；复制 prompt；`toast` 提示
- 缺：**参数-切片命中矩阵**（改一个参数看不出"哪些切片因此开/关"）；**场景之间无法对比**；架构图是静态 SVG（无 hover/聚焦/连线动画）；`benchmark` 是折叠 `<details>` 里的裸表格；无 URL 持久化（刷新丢参数）；无"参数变更 diff"

### 1.3 一句话判断

两个页面的**信息密度已经很高，交互密度很低**。升级方向明确：把已有的"数据"翻译成"图形 + 可操作控件"，而不是补数据。

### 2.7 现成的「画布 + 交互」实现（可直接借鉴/抽取）

**① `src/app/stack/TechArch.tsx`（35 KB）—— SVG 字符串注入 + 指针拖拽**
- 渲染方式：`buildTechArchSvg(arch, theme, { hooks: true })` 产出整张 SVG 字符串，用 `dangerouslySetInnerHTML` 注入一个 `<div>`（L836-845）
- 拖拽：容器级 `onPointerDown/Move/Up`，用 `(e.target as Element).closest('[data-node]')` 做事件委托；缩放补偿 `scale = canvasRef.current.clientWidth / arch.width`（L218）
- 编辑态 `CanvasEdits` 存 localStorage（`arsenal-tech-arch-edits-v1`）
- 主题切换 5 档（`CANVAS_THEME_OPTIONS`）、PNG 导出（canvas `scale=2`，L310-313）、Markdown 导出

**② `src/app/stack/ArchDiagram.tsx`（29 KB）—— 五种交互模式 + 键盘**
- `type Mode = 'focus' | 'reach' | 'route' | 'lens' | 'story'`，对应 `DiagramView` 的 `{focus, lit, litPipes, litLanes, tone}`
- 渲染：`buildArchDiagramSvgInteractive(model, theme, view)` → `toResponsiveSvg(...)` → `dangerouslySetInnerHTML`（L749）
- 交互：点击方块（事件委托读 `data-slot`）、`Escape` 清空、`←/→` 切导览章节等键盘快捷键（L291 `window.addEventListener('keydown')`，输入框内不响应）
- **强约束（文件头 + `graph-check.ts`【8】）**：不传 view、不开 interactive 时，产物必须与加交互前**逐字节相同**

### 2.8 依赖现状与「手写 SVG vs 引库」评估

`arsenal-web/package.json` 实测：

```json
"dependencies":    { "next": "14.2.33", "react": "18.3.1", "react-dom": "18.3.1" }
"devDependencies": { "@types/*", "autoprefixer", "postcss", "tailwindcss 3.4.17",
                     "typescript 5.5.3", "tsx", "playwright-core ^1.63.0" }
```

**运行时依赖只有 3 个：next / react / react-dom。没有任何图表库。** `playwright-core` 仅视觉断言层用，不进产物。

| 方案 | 代价 | 结论 |
|---|---|---|
| 手写 SVG（复用现有） | 中等代码量，但度量/折行/调色板/动效/导出/交互钩子全部现成；零新增依赖；符合 `output:'export'` 与 README 明文立场 | **推荐** |
| 引 d3 | `d3` 全量 ~270 KB；`d3-selection` 与 React 的 DOM 所有权冲突（React 管 DOM，d3 也管，本站用 `dangerouslySetInnerHTML` 绕开这层，引 d3 反而要拆掉现有范式）；且违反"依赖尽量少"的硬规矩 | 不推荐 |
| 引 recharts / visx / echarts | 它们是**图表库**（折线/柱/饼/坐标轴），而本次要的是"分层流程图、命中矩阵、架构图、对比看板"——**都不在它们的语义里**，用了也得大量定制；echarts 体积 ~1 MB 且与纯静态导出的 SSR 不友好 | 不推荐 |

**唯一值得评估的增包**：若一定要做"拖拽 + 缩放 + 平移画布"，可考虑 `d3-zoom`（~10 KB，只做手势，不管 DOM）。但 `TechArch.tsx` 已经用 20 行 pointer 事件实现了拖拽带缩放补偿，**没有必须引的理由**。

### 3.4 「加一个字段」到底要改几处（核实结论）

**结论：加字段 ≠ 加一类事实源，不适用"四处"那条规矩。实际是 3~4 处，且第 1 处经常被漏。**

| # | 位置 | 必改？ | 说明 |
|---|---|---|---|
| 1 | **`tools/content/<模块>.py`** | ✅ **必改（最容易漏）** | README 数据流图明写"改内容改这里，不要改 JSON"；JSON 是生成物。只改 JSON 不改 py，下次跑 `build-content.py` 字段会被**静默抹掉**，而前端已经依赖它 → 页面白屏或空图 |
| 2 | 跑 `python tools/build-content.py` → JSON 落盘 | ✅ | 否则字段不存在 |
| 3 | **TS 类型**：`src/lib/content-types.ts`（cookbook）或 `src/lib/case-types.ts`（cases） | ✅ | 不加则 tsc 红（根配置 521 文件 + `.verify` 两套闸门都跑） |
| 4 | 前端消费组件 | ✅ | 本次升级的主体 |
| 5 | `scripts/sync-content.mjs` 加校验 | ⭕ 建议 | **只有需要"字段必须存在/必须满足某形状"时才加**。同步脚本不裁剪字段，所以不加也能跑通；但加了才能保证"6 条场景都有这个字段"（`benchmark` 的坑正是没加校验造成的） |
| 6 | `.verify/project-check.ts` | ❌ 不需要 | 它只在【?】里断言 `arsenal-rules/arsenal-cookbook/arsenal-stacks` 三个**目录存在**，与字段无关 |
| 7 | README 目录树 | ❌ 不需要 | 只在**新增一类事实源目录**时才改 |

> 一句话：**在已有事实源里加字段 = 改 py 生成器 + TS 类型 + 前端组件（+ 可选 sync 校验）；"四处"那条规矩（sync-content.mjs + resolver + project-check.ts + README 目录树）只适用于新增一类文件型事实源。**

- **`out/` 新鲜度闸门**（`visual-check.ts` L91-149）：`FRESHNESS_ROOTS` 含 `arsenal-cases` 和 `arsenal-cookbook`。**改了事实源 JSON 而没重建 `out/`，整层跳过（不算绿也不算红，退出码 2）**。`src/generated/` 被刻意排除（sync 每次都重写 mtime）。→ 每次改事实源后必须 `node scripts/next-run.mjs build`

### 4.3 `project-check.ts`（413 项）的【13】导航与页签契约

- ① `Shell.tsx` 里每个 `{ href: '...' }` 都要有对应的 `src/app/<href>/page.tsx`

### 5.3 风险点（按严重度排序）

**R1 · 🔴 严重｜`/cases` 切场景会运行时崩溃（`kase.benchmark` 无守卫）**
- 是什么：`CaseLab.tsx:628 / 634 / 642 / 655` 直接读 `kase.benchmark.title/columns/rows/conclusion`，但 6 个场景里 **4 个（hotspot-cache / async-pipeline / high-throughput-io / wide-table-search）没有 `benchmark` 字段**
- 为什么没被发现：静态导出只预渲染默认场景（`cases[0]` = huge-rowcount-rdb，有 benchmark），所以 build 与 45 张视觉矩阵全绿；**但用户点左侧列表切到那 4 个场景时 React 会抛 TypeError**
- 怎么规避：先把 `benchmark` 改成可选并加守卫（`{kase.benchmark && (<details>…</details>)}`），或补齐 4 个场景的 benchmark（改 py 生成器 + 重跑 build-content）。**建议本次升级第一步就修掉**，否则新 UI 叠在崩塌的组件上无法验证

**R2 · 🔴 严重｜A5 对比度：新增图形的红/紫/淡灰文字会红**
- 是什么：正文 ≥12px 要求 ≥4.5:1。实测 `#5E6E67` 在 surface 上仅 3.31:1、`fgFaint` 在 surfaceMax 上 4.40:1、`#E5484D` 在 surfaceHi 上 4.15:1
- 为什么：项目 2026-09-23 刚把 `fgFaint` 从 `#5E6E67` 提到 `#80918A`，但**硬编码旧值仍散落在多个文件里**；新图形很容易顺手抄走
- 怎么规避：新 UI 一律用 Tailwind token（`text-fg/fgMuted/fgFaint`）；图上文字用 `DIAGRAM_PALETTE.dark.{fg,fgMuted}`；**禁止 `text-fgFaint` 配 `bg-surfaceMax`**；红色小字控制在 <12px 或加大加粗

**R3 · 🔴 严重｜A1 横向溢出：SVG 撑破容器**
- 是什么：`scrollWidth - clientWidth > 0` 即红，且 2026-09-22 曾出现"390px 视口下 15 个页面一致溢出 +53px"的 P0
- 为什么：SVG 若带固定 `width/height` 且没有 `viewBox` + 自适应，会按固有像素宽度撑开父容器；grid/flex 列宽还会被 overflow-hidden 的子元素间接撑开（assert.mjs 特别为此加了"被裁剪元素"线索）
- 怎么规避：所有新 SVG 必须 `viewBox` + `className="w-full"` + `style={{maxHeight: N}}`；复用 `toResponsiveSvg()`；容器加 `min-w-0`（grid/flex 子项默认 `min-width:auto` 是溢出元凶）；**改完必须在 390px 视口实跑一次**

**R4 · 🟠 高｜`out/` 新鲜度闸门导致整层跳过**
- 是什么：`visual-check.ts` 发现事实源（`arsenal-cases` / `arsenal-cookbook`）比 `out/index.html` 新 → 整层跳过，退出码 2
- 为什么：本层测的是真实页面，拿旧产物判会既有假红也有假绿。历史上因此误报过 3 条"回归"
- 怎么规避：**每次动事实源后先 `node scripts/next-run.mjs build` 再 `npm run verify:visual`**；把这一步写进第二阶段的任务清单，别等 CI 提醒

**R5 · 🟠 高｜新增顶层路由会打断 45 张矩阵**
- 是什么：`visual/shoot.mjs` 的 `EXPECTED = {fixedPages:10, urls:15, shots:45}` 写死；`.verify/visual-check.ts`【3】还会交叉核对「断言张数 vs manifest 张数」
- 为什么：矩阵自动发现，但期望值手写 —— 加一个顶层页面目录就 mismatch；加 `/cases/[id]` 二级路由则会被判"未归类"而**不进矩阵（永远不被断言）**
- 怎么规避：**优先在现有 `/cases` 路由内做页签/视图切换，不新增路由**；若必须新增顶层路由，同步改 `EXPECTED` + `node visual/shoot.mjs` 重跑 + 更新 README 与档案项数

**R6 · 🟠 高｜`verify:cases` 的源码文本断言会卡住重构**
- 是什么：`page.tsx 渲染了 CaseLab`（字面量 `<CaseLab`）、`CaseLab 是客户端组件`（字面量 `'use client'`）、`NAV 有 href: '/cases'`
- 为什么：这是"按钮在、点进去是空的"那类事故留下的契约
- 怎么规避：拆子组件时**保留 `CaseLab` 这个名字作为入口组件**（内部再拆）；或改断言并同步说明。不要默默改名

**R7 · 🟡 中｜深色主题 token 一致性（三套调色板并存）**
- 是什么：`DIAGRAM_PALETTE.dark`（card `#1A2220` / fgFaint `#5E6E67`）／`themePalette('dark')`（card `#16211F` / faint `#6A7F80`）／tailwind token（`surface #131917` / fgFaint `#80918A`）**三套深色值互不相同**
- 为什么：历史演进；`arch-diagram` 的 `fgFaint #5E6E67` 已经是不达标的旧值
- 怎么规避：新图形按"同屏的邻居是谁"选一套并只用一套；**图上文字优先 `DIAGRAM_PALETTE.dark.fg/fgMuted`，避开它的 `fgFaint`**；不要为了统一去改 `DIAGRAM_PALETTE`（`verify:graph`【8】会断言非交互产物逐字节相同）

**R8 · 🟡 中｜SVG 中文文本宽度度量（项目踩过的坑）**
- 是什么：`CaseLab.tsx:24-33` 的注释记录了原话："写死宽度在「样本元数据」这类中文标签上会溢出 —— SVG 的文字不会自动换行，溢出后表现为「标签压在节点边框上」，而且只在某些场景才出现"
- 为什么：SVG `<text>` 不换行、不裁切，宽度必须自己算；且"只在某些场景才出现"意味着**手工测试容易漏**
- 怎么规避：所有节点宽度走 `Math.max(下限, Math.round(textWidth(label, fs)) + padding)`；长标签走 `wrapText`；**给最长的一类中文标签单独在 390px 视口下看一次**

**R9 · 🟡 中｜改事实源不跑 `build-content.py` 会被静默抹掉**
- 是什么：`arsenal-cases/*.json` 与 `arsenal-cookbook/*.json` 是 `tools/content/*.py` 的**生成物**，不是手写源（README 明写"改内容改这里，不要改 JSON"）
- 为什么：与"手写事实源"的直觉相反；只改 JSON 当下能跑，下次有人跑生成器字段就没了
- 怎么规避：加字段一律先改 py → 跑 `python tools/build-content.py` → 再 `npm run sync`；**在字段上加 sync 校验**（防止像 `benchmark` 那样只有 2/6 场景有）

**R10 · 🟢 低｜纯静态导出（`output:'export'`）的能力边界**
- 是什么：`next.config.mjs` 硬写 `output:'export'`、`images.unoptimized:true`、`trailingSlash:true`
- 影响：① 不能做 SSR/ISR，交互全在客户端；② 若用 `useSearchParams()` 做参数持久化，**必须 `<Suspense>` 包裹**，否则 `next build` 在静态导出下会报错；③ 新增依赖会直接进 bundle，体积无服务端分摊（`cases.json` 已 382 KB）
- 怎么规避：不引运行时依赖；参数持久化若麻烦就退回组件内 state（现状）；需要跨页状态用 localStorage（沿用 `TechArch` 的 `arsenal-tech-arch-edits-v1` 写法）

### 5.4 依赖建议

**结论：不引入任何新的 npm 运行时依赖。**

理由四条：
1. **项目已有三套手写 SVG 渲染器 + 一套字符度量 + 一套内嵌动效**，覆盖本次全部图形类型；README 明确写 `src/lib` 都"不引绘图库"，这是明文立场
2. 本次要的图形（分层流程图、命中矩阵、对比看板、架构图）**都不在 d3/recharts/echarts 的语义范畴内**，引了也要大量定制，收益为负
3. `output:'export'` 纯静态 + 硬规矩"依赖尽量少"；`cases.json` 已 382 KB，再叠一个 270 KB 的 d3 或 1 MB 的 echarts 会明显拖慢首屏
4. `d3-selection` 与 React 的 DOM 所有权冲突，会逼着我们拆掉已经跑通的「SVG 字符串 → `dangerouslySetInnerHTML` → 事件委托」范式，而这个范式正被 `verify:graph` 的 68 项断言守着

**唯一可以松动的情况**：若最终要做"自由缩放 + 平移 + 多指手势"的画布，可只引 `d3-zoom`（约 10 KB，只算手势不碰 DOM）。但 `TechArch.tsx` 已用 20 行 pointer 事件做了"拖拽 + 缩放补偿"，**当前没有必须引的理由**。
