# 架构图谱（/arch）优化方案

> 盘点时间 2026-09-23 · 只读盘点，未改任何代码
> 盘点范围：`src/app/arch/**`、`src/lib/arch-*.ts`、`src/lib/archify-ir.ts`、`src/app/archify/**`、`src/app/stack/TechArch*`、`arsenal-server` 的 Archify 接口

## 一、结论先行

1. **「架构图谱」这名不副实**：六个视图里只有「技术架构」是真图（可拖拽、可改、可导出），其余五张是**写死坐标的静态 SVG 插画**——`diagrams.tsx` 全文件零事件处理器，唯一"动"的是 CSS 动画。
2. **卖点和数据层打架**：页面主打「换一份档案就讲另一个项目」，但五张图按本平台的形状写死（5 个能力域、3 个出口、5 层应用带）。**换档案 = 错位、留白、甚至显示 `undefined`**。这是 P0，不是优化项。
3. **最大的浪费不是缺功能，是资产没接线**：`arch-geometry.ts`（几何校验）全仓零 import，`arch-graph.ts`（可达/最短通路算法）只有 1 个消费者，而它们正是五张图最缺的东西。**修 P0 的那一步，顺手就能把闲置引擎接上**。
4. **违背平台自己的第一原则**：「一份数据三种出口（人查 / 给 AI 用 / 拿代码验）」——/arch 现在只有「人查」一条腿，五张图不能导出、AI 拿不到、代码验不了。

## 二、现状体检表

| 视图 | 布局性质 | 交互 | 导出 | 换档案安全 | 备注 |
|---|---|---|---|---|---|
| 业务 | 写死（5 域 / 3 出口，间距按 5 份算） | 无 | 无 | ✗ 数量不符即重叠 | `diagrams.tsx:264-267` |
| 数据 | 写死（3 资产 / 4 管道 / 3 消费方） | 无 | 无 | ✗ 消费方标题硬编码 `['前端','后端','导出'][i]` | `:413`，第 4 个显示 `undefined` |
| 应用 | **半真**（chips 会按像素换行） | 无 | 无 | ✗ 契约块按 5 层算 y | `:514-522`；`:499` 用中文硬比 `layer.name==='页面层'` |
| 产品 | 写死 | 无 | 无 | ✗ 严重度行走 `liveStats`，**永远是本平台数字** | `arch-views.ts:197-203` |
| 项目 | 写死（唯一真布局是验证链比例条） | 无 | 无 | ✗ 目录按 8 项排 | `:768-775` |
| 技术 | **真图**（arch-canvas 模型 + 布局） | 拖拽/改名/增删节点/加连线 | PNG·SVG·MD | 不适用（跟装配台选型走） | `TechArch.tsx:145/194/478/604` |

**其他确凿问题**（均已 grep 复核）：

- `arch-geometry.ts` 零 import，全仓只在 `arch-diagram.ts:46` 的注释里被提到；连带 `DIAGRAM_LAYOUT` 一并闲置。
- `arch-motion.ts` 的 `amRise/amFlow/amPulse/amBreathe/amSpin/amGlow` 六个导出零引用，只有 `svgMotionStyle` 在用。
- `app.routes` / `app.endpoints` 在 `arch-views.ts:129-130` 解析了但**无人消费**——档案里写了页面上看不见。
- `METRIC_TOKENS`（`arch-profile.ts:119`）无参调用会漏掉 `verify.total`，且全项目无人 import，是死导出。
- 无 `addEventListener('storage')`：`picks-store.ts:9-10` 声称"storage 事件兜底"，实际没接 → 在 `/stack` 改选型后回 `/arch` 不刷新。
- 档案**只能导入不能导出**（`profile-store.ts:14` 写 localStorage，无导出按钮）；导入成功提示在配额/隐私模式下会静默吞异常仍弹"已导入"。
- 无障碍：六张图只有一句 `aria-label`（`diagrams.tsx:232`），内部节点无任何 `<title>`。

## 三、P0 — 不修就是坏功能（建议先做这三条）

| # | 问题 | 改法 | 验收 |
|---|---|---|---|
| P0-1 | 五张图坐标写死，换档案就崩 | 把 `cardW/gap/x` 全部改为**按数据长度算**；`viewBox` 高度也跟着算 | 造两份"异形档案"（3 个能力域 / 8 个能力域），断言无重叠、无越界 |
| P0-2 | `['前端','后端','导出'][i]`、`layer.name==='页面层'` | 消费方标题改用 `dataConsumers[i]`；应用层加 `mono?: boolean` 字段，别比中文 | 档案里写 5 个消费方 / 改层名，图不错位、字体不乱 |
| P0-3 | 产品视图严重度永远是本平台数字 | 档案可覆盖 `severity`，默认回落 `liveStats` | 换档案后 MUST/NEVER 数字跟着变 |

> **P0-1 的验收直接把闲置的 `arch-geometry.ts` 接上**：它已经有 `checkDiagramGeometry()`（8 种错误码）+ `parseSvgRects()`，就是干这个的。一份工作修两个问题。

## 五、P2 — 深水区（先别动）

- P2-1 五张图支持可编辑画布：把 `CanvasEdits` 从 `/stack` 复用到 `/arch`，改完能存回档案 → 闭环。**这是终局形态，但依赖 P0 全部完成**。
- P2-2 内置模型库（现在只有 2 个：`self-arch` + 一个）。
- P2-3 `schema_version` 迁移 + 真校验（现在是手写 `archifyIrShapeIssues`，无行号定位）。

## 六、明确不建议做

| 不做 | 理由 |
|---|---|
| 给五张图加力导/分层布局引擎 | 它们是「讲解图」不是「探索图」——固定语义位置（能力域在上、出口在下）反而更清楚。参数化即可，不必求解器 |
| 多档案 diff / 版本对比 | 单人 + 小团队（≤10）场景用不上 |
| 给插画加 3D / 视差 | 与平台"严肃工具"调性冲突 |

## 七、验收口径

P0 三条的判据必须**能被代码断言**，不能靠肉眼看图：

1. 新增一层 verify（或并入现有视觉断言层）：喂 N 份异形档案 → 解析 SVG → 断言矩形两两不相交、全部落在 viewBox 内。
2. 断言写完**反着验一次**：故意把 gap 改小，断言必须变红，再还原复跑变绿。
3. 六视图页签 ↔ 渲染分支的契约，按现有 `project-check.ts` 的口径（把源码当数据断言）补上。
