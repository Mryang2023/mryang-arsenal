## 二、B0 · 前置：修一个线上 Bug（必做，最先做）

### 证据（已实测核实）

```
async-pipeline.json            benchmark=缺失
genomic-sequence-store.json    benchmark=有
high-throughput-io.json        benchmark=缺失
hotspot-cache.json             benchmark=缺失
huge-rowcount-rdb.json         benchmark=有
wide-table-search.json         benchmark=缺失
```

- `src/lib/case-types.ts:110` 把 `benchmark` 声明为**必选字段**（无 `?`）——**类型对数据撒了谎**。
- `src/app/cases/CaseLab.tsx:628` 无守卫读 `kase.benchmark.title`。
- 默认场景 `cases[0]` 按 `meta.order` 是 `huge-rowcount-rdb`，**它恰好有 benchmark** → 静态预渲染不崩、`shoot.mjs` 45 张全绿，**用户点到第 3 个场景起才开始白屏**。

### 修复动作

| # | 动作 | 说明 |
|---|---|---|
| B0-1 | 全量核字段 | 用同一方法（`case-types.ts` 每个必选字段 × 6 个 case JSON 的实际存在性）核一遍，**别只修 benchmark 一个**；cookbook 4 条同样核一遍 |
| B0-2 | 类型改可选 + UI 守卫 | `benchmark?:` 且 `CaseLab.tsx` 加空态守卫（无数据时显示「本场景未提供性能参照」而非崩） |
| B0-3 | 补数据（建议做） | 给 4 个缺失场景补 `benchmark`。**必须改 `tools/content/*.py` 再跑 `build-content.py`** —— 事实源是 py 生成物，直接改 JSON 会被静默抹掉 |
| B0-4 | 补断言 | 新增「类型声明的必选字段 ↔ 事实源实际字段存在性」一致性断言，放在结构导出层。这是 690 条断言没抓住它的根因 |

**验收**：6 个场景逐个点击不白屏；新断言注入错误后必须变红（反着验一次）。

## 三、P0 · 五张新图（本次升级主体）

### cookbook（`/blueprints/[id]` 详情页）

| ID | 图 | 数据源 | 让人看清什么 |
|---|---|---|---|
| **P0-1** | 垂直切片链路图 | `flow[]` | 一条请求从入口到 SQL 怎么走。**必须支持回程边** —— `crud-basic` 末步回到 `web`（异常处理器旁路）、`async-transaction` 末步回到 `client`（异步闭环），画成直线就是画错 |
| **P0-2** | 包-文件-层 树图 | `files[].path` + `highlights.length` | 15 个文件按真实路径建树，叶节点挂锚点徽标，配色按 `files[].layer`。与 P0-1 hover 联动 |
| **P0-3** | 规则 × 文件 覆盖矩阵 | `relatedRules[]` × `files[].highlights[].rule` | 25 条规则里**哪几条真有代码证据**。顶部真值统计条 `有锚点 14 / 25`；`X+Z ≠ Y` 时红字报「数据不自洽」 |

### cases（`/cases` 结果区）

| ID | 图 | 数据源 | 让人看清什么 |
|---|---|---|---|
| **P0-4** | 参数 × 切片 命中矩阵 | `drivers[].levels[]` × `slices[].when` | 调参之前就知道会牵动哪些切片；列头敏感度条回答「哪个参数才是真正的分水岭」。**四态**：条件命中 / 无条件命中（`when:{}`）/ 该切片不约束此参数 / 未命中 |
| **P0-5** | 架构图交互化 | `case-synth` 输出 + `slices[].decision` | hover 出「为什么有这个节点」、点击锁定过滤切片、参数变更的 diff 动画 |

### 关键硬事实（做错就返工）

1. **两套 layer 词表，不要映射成一套**
   - `flow[].layer`（调用层）= `client / web / service / repo / sql / concurrency`
   - `files[].layer`（构件层）= `web / dto-in / dto-out / service / repo / domain / exception / common / sql / config / integration / structure / test`
2. **`flow` 不是单向链**，数据结构必须是「节点 + 有向边」而非数组顺序。
3. **`slices[].when` 可以是 `{}`**（hotspot-cache 的「可观测与降级兜底」）= 无条件命中，不能当成未命中。
4. 匹配不到代码文件的链路节点标 `fgFaint` 且**不可点**，浮层写「无对应代码文件」—— 不假装可点。
5. 架构节点拿不到理由时显示「未标注原因」，**不编造**看似合理的解释。

## 五、技术裁决

| 问题 | 裁决 | 理由 |
|---|---|---|
| 引图表库？ | **不引** | 现有三套手写 SVG 渲染器 + 度量 + 动效已覆盖全部需求；`output:'export'` 纯静态 + README 明文不引绘图库；d3-selection 与 React DOM 所有权冲突会逼我们拆掉被 68 项断言守住的现有范式 |
| 动事实源字段？ | **不动**（A 方案） | 关联在 `case-synth.ts` 合成期确定。真要加：py 生成器 + TS 类型 + 前端组件，**3 处**（不是 4 处） |
| 跨场景对比做路由？ | **抽屉 + URL 参数** | 见决策 #5 |
| 先做样板？ | **是**，先 `crud-basic` | 见决策 #7 |
| 交互深度？ | hover + 点击锁定 + 键盘可达 + reduced-motion 全要 | 信息不能只存在于 hover 里 |

### 可复用资产（直接拿来用，别重写）

- 字符度量：`@/lib/arch-diagram` 的 `charWidth` / `textWidth` / `wrapText`（CJK≈1em、ASCII≈0.55em）—— **中文标签溢出坑的官方解法**
- 调色板：`DIAGRAM_PALETTE.dark`、`themePalette('dark')`、`layerTheme(layer)`、`stack/palette.ts` 的 `TONE`
- 动效：`@/lib/arch-motion` 的 `svgMotionStyle` / `amRise` / `amFlow` / `amPulse` / `amBreathe` + `<Reveal i>` / `ui-rise`
- 交互范式：`stack/TechArch.tsx`（SVG 字符串 → 事件委托 → 拖拽缩放补偿）、`stack/ArchDiagram.tsx`（五模式 + 键盘）
- 分层渲染器：`arch-layered.ts` 的 `buildLayeredSvg(data,theme)`，写 `Feature.flow → LayeredArchData` 适配器即可（**待确认能否表达回程边**）
- 纯函数：`case-synth.ts` 的 `enumerateParams` / `cornerParams` / `synthCase` 可穷举，命中矩阵不用新数据

## 七、风险护栏（按严重度）

| 级别 | 风险 | 规避 |
|---|---|---|
| 红 | **A1 横向溢出**：25×15 与 8×19 两个宽幅矩阵在 390px 视口必溢出（历史上 15 页一致溢出 53px） | 新 SVG 必须 `viewBox` + `w-full` + `maxHeight` + 容器 `min-w-0`；宽幅图放**横向滚动容器**（保留「可看全」，不缩放到不可读）；改完必跑 390px |
| 红 | **A5 对比度**：正文 ≥12px 要 ≥4.5:1 | 一律用 Tailwind token。**禁止 `text-fgFaint` 配 `bg-surfaceMax`**（实测 4.40:1）；现存硬编码旧值 `#5E6E67`（3.31:1）不许复制到新代码 |
| 红 | **R4 新鲜度闸门**：改了事实源没 `next build`，视觉层整层跳过（退出码 2，既不绿也不红） | 跑视觉层前先 `node scripts/next-run.mjs build` |
| 橙 | **R6 源码文本断言**：`page.tsx` 必须含字面量 `<CaseLab`、`CaseLab.tsx` 必须含 `'use client'` | 拆子组件时保留 `CaseLab` 作为入口名 |
| 橙 | **R7 三套调色板并存** | `DIAGRAM_PALETTE` 不许改（`verify:graph` 断言逐字节相同）；新图明确说用哪一套 |
| 橙 | **R9 事实源是 py 生成物** | 改字段/补数据必须改 `tools/content/*.py` + 跑 `build-content.py` |
| 橙 | 同一文件多处改动并行编辑会静默丢改 | 串行改；加 prop/state 前先 grep 同名声明 |

### 建议新增断言

1. **字段存在性一致性**（B0-4）：`case-types.ts` / cookbook 类型的每个必选字段 ↔ 事实源实际存在性。约 `cases 必选字段数 × 6 + cookbook 必选字段数 × 4` 条。
2. **图形几何**：新图的版式常量导出后复用，断言「节点不越界」「回程边存在且指向正确泳道」。
3. 新增断言需同步改：`package.json` + `scripts/verify-all.mjs`(LAYERS) + `.verify/lib/report.ts`(LAYER_NAMES) + `.verify/meta-check.ts`(CHAIN_ORDER) + 档案 `verifyChain` + README 两处。
