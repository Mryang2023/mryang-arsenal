## 0. 决策先行

| 项 | 结论 |
|---|---|
| 诊断 | 不是「元素太少」，是**三类已有资产没兑现**：画布模型（`arch-canvas.ts` 的 `CanvasNode` / `CanvasEdits` / `themePalette`）、网格底纹（`.grid-bg`）、动效库（`arch-motion.ts`）、进度环（`DeliveryDeck` 里的 `ProgressRing`）—— 装配台只用了它们的**静态 SVG 出图**，交互层一个都没接。 |
| 观感普通的直接原因 | 装配区 = 33 个等宽 172px 卡片 `flex-wrap`，**没有空间语义、没有权重分级、没有连线（只有 `→` `↓` 文本字符）、没有焦点层级、没有动效**。 |
| 主线 | 一条视觉谱系走到底：深色军事工业 + 黄铜。**不新增第二种配色**；新增的「权重」「状态」用尺寸 / 边框 / 底纹 / 抬升表达，不用新颜色。 |
| 分期 | **P1 形**（观感与空间，7 条）→ **P2 用**（交互与决策，7 条）→ **P3 深**（智能与可分享，4 条）。共 18 条。 |
| 建议先做 | P1 全做 + P2 的 S2-2/S2-4/S2-7。这 10 条解决「太普通」和「不好用」，且**不动导出产物、不动 33 维数据语义**，风险最低。 |
| 明确不做 | 不引拖拽库（dnd-kit / react-dnd）、不做 auto-fix、不做后端持久化与多人协作、不新增配色谱系、不改 `composeStack` 纯函数语义。 |

## 2. 视觉系统契约（装配台专属，增量不推翻全局）

### 2.1 主题与色彩

沿用全局 token，**只新增 4 个装配台变量**（写进 `globals.css` 的 `:root`，不与既有 token 冲突）：

| CSS 变量 | 值 | 用途 |
|---|---|---|
| `--stack-bench` | `#101614` | 装配台面底色（比 `surface` 更暗一档，让卡片浮起来） |
| `--stack-bench-grid` | `rgba(36,48,41,0.55)` | 台面网格线（= 现有 `.grid-bg` 的线色，34px 一格） |
| `--stack-part` | `#1A2220` | 已装零件卡片底（`surfaceHi`） |
| `--stack-part-hi` | `#212B28` | hover / 选中卡片底（`surfaceMax`） |

语义色**只允许** `palette.ts` 的 TONE 五色，含义不许复用：

| 语义 | HEX | 场景 |
|---|---|---|
| bad | `#E5484D` | 必需件缺失、能力无人提供 |
| warn | `#D9A441` | 组合隐患、EOL 基底 |
| ok | `#7FA650` | 已装且能力闭环 |
| idle | `#5E6E67` | 未使用、可选件留空（**正常态，不是错误**） |
| info | `#6E8FA8` | 说明、旁路件 |

> 约束：正文色最低 `fgFaint #80918A`（3 个背景下均过 WCAG AA 4.5:1，见 `visual/assert.mjs` A5）。新增任何颜色前先跑 A5。

### 2.2 字号（收成 4 档，消灭 9px 连排）

| 档 | 大小 / 行高 | 用途 |
|---|---|---|
| title | 14px / 20px | 结论条主文案、面板标题 |
| strong | 12px / 18px | 卡片零件名 |
| body | 11px / 16px | 卡片能力行、说明（= `text-2xs`） |
| meta | 10px / 15px | `provides` 之类的字段标签、计数 |

字距一律 `0`（`letter-spacing: 0`），数字用 `.stat-num`（tabular-nums）。

### 2.3 层级 / 深度 / 动效

| 层 | 表现 |
|---|---|
| L0 台面 | `--stack-bench` + `.grid-bg` 34px 网格，无边框 |
| L1 泳道面板 | `surface` + `border-line` + `rounded-lg` |
| L2 零件卡 | `surfaceHi` + `border-lineHi`；已装件用 `tone.soft` 底 |
| L3 悬浮 | `surfaceMax` + `border-lineHi`，`transition 150ms` |
| L4 选中 | `--stack-part-hi` + `box-shadow: 0 0 0 1px #D9A441, 0 12px 32px -16px rgba(0,0,0,0.9)`（=`shadow-lift`），**同时台面其余卡片降到 0.96 不透明度** |

动效（复用 `arch-motion.ts`，不新造）：
- 卡片入场：`fade-up`（已有 keyframes），按泳道顺序 `staggerDelay = laneIdx*40 + slotIdx*18` ms，上限 320ms。
- 请求链路点亮：`amFlow('slow')` 流动虚线；仅在该泳道 `pipelines` 有链路时启用。
- 隐患卡：`amPulse()` 只在**新出现**的隐患上跑一次（不常驻闪烁，否则等于噪音）。

### 2.4 卡片三档尺寸（解决 N-2）

| 档 | 宽度 | 判定 |
|---|---|---|
| 核心 | 208px | `inPipeline === true`（在 `arch.pipelines[lane]` 里） |
| 常规 | 172px | 其余必选 / 建议件 |
| 旁路 | 148px | `inPipeline === false` 且该泳道存在链路（旁路件） |
| 未用 | 同档宽 + `opacity .72` | 未选且非必需 |

### 2.5 布局与响应式

- `≥1280px`：左装配区 / 右交付预览 `xl:grid-cols-[minmax(0,1fr)_minmax(0,1.05fr)]`（现状，保留）；右栏 `sticky top-4`。
- `768–1279px`：单列，交付预览跟在装配区后；**卡片最小宽度 148px**，容器 `min-w-0` + `flex-wrap`（防 V2-02 溢出）。
- `<768px`：卡片 `grid-cols-1` 全宽；形态选择器改横向滚动条（**修 V2-02**）。
- 触摸目标 ≥44px：卡片移除按钮从 16px 改 32×32 的点击区（视觉 20×20，用 padding 撑）。

## 4. 交互契约（每次改动都要满足）

| 状态 | 必须有的表现 |
|---|---|
| default | 卡片三档尺寸 + 状态色边框（虚线 = 未装 / 必缺） |
| hover | `surfaceMax` + `border-lineHi`，150ms |
| focus-visible | brass ring 1px + 2px offset（键盘可见） |
| selected | L4 抬升 + 同层降噪至 0.96 |
| disabled / 不可选 | 降透明度至 0.5 + `cursor: not-allowed` + tooltip 说明原因 |
| loading | 出图类操作显示骨架块（不用 spinner 遮整屏） |
| error | 结论条转 bad 态 + 具体缺口数量与位置，不给空话 |
| empty | 至少一句「装了会怎样」+ 一个可执行动作（修 V2-13） |
| 恢复 | 撤销 / 重做覆盖全部写操作；刷新后从快照恢复且**首帧不覆盖用户数据** |

## 5. 验收门禁（挂现有 verify 链，不另起炉灶）

1. **源码即数据**：新增页签 / 视图 / 状态必须同步 `TabId` ↔ `tab === 'x'` 两处（硬约定 6），由 `.verify/project-check.ts` 断言；解析前先 `stripComments()`。
2. **视觉层现测**：改 UI 后先 `node scripts/next-run.mjs build`，再跑视觉层（`out/` 陈旧会红在旧产物上，不代表现在的代码）。判据 A1–A7 见 `visual/assert.mjs`。
3. **断言反着验**：每条新断言注入一次错误确认真红，还原后复绿；还原用 `git checkout --` 或 `newline=''` 写回（防 CRLF 污染）。
4. **数据字段**：任何新增选项属性走 `tools/content/*.py` → `build-content.py` → `sync-content.mjs`，禁止直接改 JSON。
5. **localStorage 键**：新增键必须有读取方，否则不加。
6. **口径同步**：增删断言要同步四处 —— 档案 `verifyChain`、README 总数句、README 分项表、重跑 `sync-content.mjs`。
7. **不做视觉验收豁免**：不写「看起来对了」就算过；每条 P1 任务至少一张三视口截图对比。

## 7. 不做的边界（写在这里是为了后面不用再讨论）

- ❌ 引入 dnd-kit / react-dnd / framer-motion —— 拖拽用原生 pointer events，动效用仓库已有的 CSS keyframes 与 `arch-motion.ts`。
- ❌ auto-fix（军火库三原则之一，装配台只做推荐不做代改代码）。
- ❌ 后端持久化、账号、多人协作、规则市场。
- ❌ 第二配色谱系 / 亮色模式（全局 `color-scheme: dark`，装配台不单独开）。
- ❌ 改 33 维语义或让 `composeStack` 回退默认值。
- ❌ P1/P2 阶段改动导出产物内容（只改呈现），产物侧的改动留给独立计划。
