### 2.1 接管协议

**前棒死了，但它的工作区里往往躺着已经写好的代码。** 那是你能救回来的东西。

| 步 | 动作 | 要点 |
|---|---|---|
| 1 | 读 `0<N-1>-running.json` 的「砍定范围」 | 那是前棒承诺的范围，接管的第一依据 |
| 2 | 盘点工作区 `git status` + `git diff --stat` | 前棒未提交的改动**全部保留** |
| 3 | 决定**救还是弃** | 属前棒声明的范围 → 救；是垃圾/脏改动 → 弃，**但必须先记下丢了什么** |
| 4 | 补最小收尾（≤10 min） | commit + 写 `0<N-1>-done.json`（`状态: "被接管"`）+ 点明哪部分是你的 |

**接管时的诚实义务（不许省）**：

- 在自己的 `0N-done.json` 写一条 `踩的坑`：`接管第 N-1 棒，它在 <时刻> 静默，实际完成度 <X>`。
- 在给下一棒的话里说明：**哪些产出是前棒的、哪些是自己的**。
- **接管 ≠ 继承自检与 review 的结论。** 前棒没做的自检段你**没资格替它签字**；但可以替它做**存在性核验 + 一次反着验**。

**交棒后自查三项（30 秒），缺任一立刻补**：
