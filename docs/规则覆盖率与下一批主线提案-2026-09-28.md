## 四、关键张力（需你拍板）

cookbook 的三层契约里 `lab.kind` 只支持 `mock-endpoint` / `thread-local`
（`src/lib/content-types.ts:157`），是为**可运行的后端模式**设计的。Tier B 的 3 条
（骨架 / 协作 / 测试）是**约定/流程类**，天然产不出「真起 HttpServer 假下游」的实验。
三条路：

- **(a) 本批只做 Tier A**：先把 Web 分层 + 不可信数据两条写了，6 条 MUST/NEVER 立即有真范例；Tier B 缓一缓。
- **(b) 扩展契约**：新增 `kind: 'convention'`，用「可校验产物」替代运行时实验（如提交信息 linter、`.gitignore` 扫描、jakarta 编译期检查）。要动 `cookbook_contract.py` + `build-content.py` + `sync-content.mjs` + 前端 `BlueprintView` 的 lab 渲染——一次不算小的契约改动。
- **(c) 挪到 cases 库**：Tier B 里适合的部分改放 cases（但 cases 目前同样没覆盖它们，等于换地方补，不解决根因）。

## 五、我的建议

先走 **(a)**：本批只写 Tier A 两条主线（Web 层分层 + 不可信数据防线），把最容易产出
真范例、也最常踩坑的 6 条 MUST/NEVER 立刻闭环；Tier B 三条统一走 **(b) 扩展契约**后再做，
避免为了塞进契约而注水（违反「写不出 bad/good 示例的不收录」）。
