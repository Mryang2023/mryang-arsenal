## 〇、结论先行

升级围绕项目唯一目标展开：**让任何 AI 生成的代码，都收敛到同一套工程规范上。**

| 战线 | 一句话 | 核心事实 |

## 三、战线 B · 校验链路打通（让已建成的能力可达、可信、可守门）

### B-1 前端接通 `POST /api/lint`（M，约 150 净）—— 全仓投入产出比最高的一件事

| 项 | 内容 |
|---|---|
| 现状 | 后端 42/69 能力就绪，前端 `arsenal-api.ts` 只有 4 个函数（archify × 2 + scan × 2），`grep 'api/lint' src` = 0 命中；`CheckConsole.tsx:318` 还在告诉用户「要等后端的 JavaParser 与 LLM 层」—— AST 那一半早就不需要等了 |
| 做法 | ① `arsenal-api.ts` 加 `lintRemote(files)`，照 `scanFacts` 的三态范式 `{kind:'report'|'rejected'|'offline'}`；② `CheckConsole` 加「后端深检」按钮，结果区合并展示（正则层本地结论 + AST 层后端结论，来源标注清楚）；③ 后端不可达时**回落本地正则层**（守住「能脱离服务器活着」原则，`arsenal-api.ts:12`）；④ 顺手修 `:318` 过期文案 |
| 验收 | 起后端 → /check 粘贴含 `@RequestBody` 无 `@Valid` 的代码 → 深检报出行号级违规；停后端 → 按钮降级、不报红错；`verify:project` 或 `parity` 加对应断言 |

### B-2 AST 层收口 + 守门（M，约 120 净）—— 堵住「最完整引擎层零回归」的洞

| 项 | 内容 |
|---|---|
| 现状 | `AstProbe.java` 236 行断言写好却 0 引用、从未编译；AST 层不遵守 `appliesTo.pathGlob`（声明外路径会触发）；5 条规则无检查器（见 B-6） |
| 做法 | ① 把 `AstProbe` 接进 verify 链：推荐**并入 `verify:parity`**（它已具备「起后端实跑探针」的全部管线，避免「加一层改五处」）——探针起不来则整组记未执行、退出 2，沿用 parity 既有口径；② `LintEngine` 的 AST 路由补 `pathGlob` 过滤（不遵守声明路径是收口欠账，README 已如实列出）；③ 反着验：临时注释一个检查器注册 → 断言必须真红 |
| 注意 | 改 parity 层项数 → 走「改四处」数字同步（档案 verifyChain / project-check 常数 / README 总数句 / README 分项表）；`verify:meta` 会盯着 |
