## 三、一棒三段（缺一不可）

**一棒 = 开发 → 自检补漏 → Code Review。**
这不是"可选的最后两步"，这是**交付的定义** —— 没跑过自检和 review 的产出，不算这一棒做完了。

| 段 | 预算 | 对准 | 回答什么 |
|---|---|---|---|
| 开发 | 60% | 方案的实施计划 | 该做的做出来了吗？ |
| 自检补漏 | 20% | **方案**（要求） | 该做的都做了吗？有没有静默失败？ |
| Code Review | 20% | **代码**（实现） | 写得住吗？有隐患吗？和项目一致吗？ |

收尾另算（约 20 分钟），见 §四。

### 3.1 开发

- **开工先砍范围**，砍到开发预算内。方案原文按"一整晚"写，砍是正常操作，不是偷懒。
  砍完写进 `<N>-running.json`，收工时对照它交账。
- 前置依赖缺失 → **降级 + 如实记录，不许硬造**。
- 阶段化推进，每阶段做完立刻验收。

### 3.2 自检补漏（完整性）

**目标：找出"看起来完成、实际没完成"的地方。** 必做五件事：

1. **验收对照** —— 把方案的「分阶段实施 / 验收标准」逐条拉成表，标 ✅ / ⚠️部分 / ❌未做。
   **对照的是方案原文，不是自己的印象。**
2. **存在性核验** —— 声称新建的文件，`ls` / `grep` 逐个确认真的在。
3. **反着验 ≥2 处** —— 挑本次新写的闸门或断言，**故意注入错误**，确认真会红，然后还原。
   > 一条从没红过的断言，和摆设没有区别。
4. **静默失败排查** —— 找"空跑通过"的检查（断言通过但样本量为 0）。必须点名。
   > 本夜高发点：① 序列点为 0 条时「列表通过」② 采集返回 `not-run` 时被当成「正常」
   > ③ 曲线输入空数组时画了一张看起来健康的空图。
5. **引用核实** —— 方案里引用的 id / 路径 / 依赖，**去仓库里查是否真实存在**。
   > 本仓踩过：方案示例里的规则 id / 路径根本不存在，照抄就错。
   > 本夜特别注意：两棒方案里的文件行号是 2026-10-13 实测值，**以你开工 grep 到的为准**。

未完成项**先补**；补不完的写进清单，具体到文件 / 阶段 / 断言编号。

### 3.3 Code Review（质量）

审**本次改动的代码**（不审全仓），五个维度：

| 维度 | 查什么 |
|---|---|
| 正确性 | 边界值、空值、并发、错误路径、类型、异步时序 |
| 安全 | 注入、路径逃逸、敏感信息硬编码、权限、对外部输入的信任 |
| 性能 | 循环内 IO、N+1、无界集合、重复计算、不必要的同步 |
| 可维护性 | 重复代码、魔法数、命名、死代码、**残留调试代码** |
| 一致性 | 与项目既有范式 / 类型体系是否一致；有没有留下"功能等价但形态不同"的平行通道 |

每条按 `[P0/P1/P2] file:line —— 问题 → 根因 → 处置` 记录。
**P0 与便宜的 P1 当场修**，修完重跑验证；其余进清单并写明为什么没修。

**本夜专项审查**：
- **棒 2 的 `RunSandbox` 要执行用户提交的源码** —— 安全审查必做：进程注入（数组参数不许拼 shell）、
  路径逃逸、输出无界、超时不杀、敏感环境变量泄漏、采完不清理进程。
- 两棒都要新增 `/autopsy` 页签 → 检查页签不抢位、不影响既有四页签。

### 3.4 段间门禁

| 关卡 | 规则 |
|---|---|
| 开发 → 自检 | 代码能编译 / 能构建通过 |
| 自检 → Review | 无未修的 P0 完整性缺陷 |
| Review → 收尾 | 无未修的 P0 代码缺陷 |

> **不许带着已知的重病往下走。** 轻问题可以记账前行，重问题不行。

## 六、项目铁律与环境备忘（每棒必带）

### 6.1 环境（漏一条那一棒就废了）

- **每条 bash 命令前必须**：`export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Windows:$PATH"`
  不加则 `ls` / `dirname` / `head` 全部 command not found。已实测有效。
- node（managed，写绝对路径）：`C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2-6/node.exe`
- python（managed）：`C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe`
- JDK：**17 corretto**（后端编译与棒 2 跑进程都用它）
- 后端 3011：`SKIP_COMPILE=1 bash arsenal-server/scripts/run.sh`（**随会话结束而死**，改 Java 必重启）
- `next dev/build` **只许** `node arsenal-web/scripts/next-run.mjs`（**它不跑 sync**）
- Git Bash 下 `npm run` exit 1 → 用 node 直跑 `npm-cli.js` 或脚本本体
- **本机没有 Chrome**：playwright 要显式 `ARSENAL_CHROME="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"`
- **java 在本 harness 常驻不了**：`run.sh`（exec）后台约 35s 静默死，`start-server.mjs` 也救不活。
  探活唯一可用姿势：**启动 + sleep 13 + fetch 探活 + kill 放在同一条 bash 命令里**（Boot 启动约 5.5s，窗口约 6s）。
  棒 2 若探不到活 → 按方案 §4 降级，**不许改代码去「修」环境问题**。
- **`spawnSync(process.execPath, …)` 曾返回 EBUSY** —— 2026-10-13 实测是**瞬时态**，spawn 现可用。
  遇到先探活再判断，别急着改代码走等价路线。
- **safe-delete ≥50 文件会拦**，且后台任务无法弹批准（stdout 全空）。清理大目录用 Python `shutil.rmtree`。
- curl 读不了 `/tmp`；给 node/python 用 **Windows 路径**（`C:\...`）。spawn node 必须传原生 Windows 路径。
