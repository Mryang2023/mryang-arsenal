## 1. 现状体检（实测）

### 1.1 内容体积

| 量 | 实测值 | 说明 |
|---|---|---|
| 场景 | 8 | 每个场景固定 4 条症状（32 = 8 × 4，结构整齐，天生可按场景分组成图） |
| 切片 | 61 | 每场景 5~8 片；`layer` 全站 10 种，但**单场景只有 2~6 条**（`hotspot-cache` 3 条、`async-pipeline`/`wide-table-search`/`virtual-thread` 各 2 条）—— 轨道图画出来是 2~6 行，不会失控 |

| # | 判据 | 现阶段 | 目标 |

## 3. 信息架构：三层路由

```
/cases                           L1  挑症状     「我遇到的是什么？」
  └─ /cases/[caseId]             L2  拧参数     「这个约束下，全局长什么样？」
       └─ /cases/[caseId]/[sliceId]   L3  拿施工图  「这一片怎么写？」
```

| 层 | 路由 | 回答的问题 | 页上的东西 | 不许出现的东西 |
|---|---|---|---|---|
| L1 | `/cases` | 我遇到的是什么 | 一句话 + 三步珠链 + **症状星群 G1** + 8 枚场景徽章 G2 + 搜索框 | 参数、代码、切片列表 |
| L2 | `/cases/[caseId]` | 这个约束下全局长什么样 | 场景横向切换条 + **参数谱 G3/G4/G12** + **架构大图 G7** + **切片轨道图 G5** + 顶部摘要微图 G6 + 导出 | 切片正文（代码 / 要点 / 出处） |
| L3 | `/cases/[caseId]/[sliceId]` | 这一片怎么写 | **决策分叉 G8** + **引线批注代码 G9** + DDL（折叠）+ **徽标带 G10** + 上下片切换 | 其它切片的正文、参数调节（只读当前参数） |

### 3.1 参数怎么跨层传

`caseId` / `sliceId` 走路径，参数走 **query** —— 不能走路径，因为参数组合是 9072 组，静态导出不可能穷举。

```ts
// src/app/cases/_lib/params-codec.ts（纯函数，verify 直接当数据跑）
// p = 按 kase.drivers 顺序各取其 level 下标，36 进制拼串；s = 溯源的症状 id
encode(drivers, params): string        // → "031201"（每字符一档）
decode(drivers, code): CaseParams      // 缺位/越界一律回退 recommended，不抛
```

- 跳转入口：`/cases/<caseId>/?p=<code>&s=<symptomId>`
- L2 改参数：**不触发 Next 导航**，用 `window.history.replaceState` 静默改写 `p`（不重跑服务端、不掉滚动位置）。
- ⚠️ `output:'export'` 下读 query 只有两条路：`<Suspense>` 包 `useSearchParams()`，或在 `useEffect` 里读 `window.location.search`。**推荐前者** —— 后者在静态页水合时序上容易先渲染一帧空参数、随后跳变。
- `drivers` 顺序：`cases.json` 里固定，构建产物确定 ✓（`sensitivity`/`inert` 也是构建期按同一顺序算的）。

### 3.2 一眼看懂怎么用：三步珠链 StepRail

三层共用同一个组件（`_lib/step-rail.tsx`），每次进页就知道自己在第几步、还剩几步：

```
  ① 挑症状 ──●──  ② 拧参数 ──○──  ③ 拿方案     ← L1：① 金黄高亮，其余降到 12% 不透明度
                                                  L2：①—② 之间连成一条金黄线，② 亮
                                                  L3：全线金黄，③ 亮
```

每颗珠子可点（回到该步），右侧同时显示当前路径：`症状：翻页越往后越慢 › 场景：亿级行关系库 › 切片：local-cache-bounded`。
这条东西总共占一行，替代 Hero 那 9 行中文。

`caseId` / `sliceId` 都是语义化 slug（实测：`hotspot-cache` / `local-cache-bounded`），不是自增序号 —— 深链人读得懂。

### 6.1 体积（提前算明白，别等 build 才炸）

61 个切片静态页 + 8 个场景页 = 69 个 `index.html`。`cases.json` 在**共享 chunk** 里（全站客户端共用一份），所以新页的增量只有 HTML + flight payload：单片约 20~30 KB → **总增约 1.5~2 MB**（`out/` 现 9.4 MB → 约 11 MB）。可接受。
前提：**L3 page.tsx 只把这一个切片的字段传下去**，不许把整个 `cases` 数组当 prop 传进 client 组件（那会让每页各自复制一份 512 KB）。
