# 部署形态动画化 · 开发计划

> 制定：2026-09-26 · 状态：**待 mryang 过目，未开工**
> 目标页：装配台 ⑤ 部署形态（`src/app/stack/steps/TopologyStep.tsx`）
> 一句话：**给每个部署形态配一台「机理台」——用分步动画回答「数据怎么查 / 怎么存 / 挂了怎么办」三件事。**

## 0. 结论先行

| 项 | 结论 |
|---|---|
| 做不做 | 做。但**不做 GIF 式装饰动画**，做「剧本播放器」——一个通用播放器 + 数据化剧本 |
| 放哪 | 嵌在 ⑤ 部署形态里（可折叠面板，默认收起），**不新增路由**；形态卡片上多一个「▷ 看机理」按钮 |
| 内容从哪来 | **新增事实源** `tools/content/stack_topology_flows.py`，走既有管道（改 py 不改 JSON） |
| 第一批做什么 | **只做 Redis 家族**（单实例 / 主从 / 哨兵 / Cluster / 多级）跑通一条完整链路 |
| 最大风险 | 内容工作量远大于代码量；且现有形态图**没有图元模型**，必须先重构才能被剧本引用 |
| 硬红线 | 动画里画的实例数 == 形态 `replicas` == 产物 K8s replicas；剧本里的数字必须可溯源，不许编造 |

## 1. 实测现状（都是刚查过的，不是猜的）

| # | 现状 | 对目标的阻碍 |
|---|---|---|
| 1 | `TOPOLOGY` 表里每个 mode 只有 `{id, label, replicas, requires, note}` | **零流转信息**。要讲「数据怎么查」，数据层根本没有这个字段 |
| 2 | 形态表是 `TOPOLOGY['cache']['*']` **按维度通配** | ⚠️ **真 bug**：Caffeine（本地缓存）也列出「主从 / 集群」。而 `TopologyPicker.tsx:86` 的文案自己写着「本地缓存没有『主从』这个概念」—— 文案与实现对不上 |
| 3 | `build-content.py:368-373` 的 **per-option 覆盖机制已存在**（`TOPOLOGY[dimId][optId]`），但**全仓一次都没用过** | 好在不用改管道，只差内容。Redis 的「哨兵 / Cluster」只能挂在这儿 |
| 4 | `topologyModeSvg()` 是 `switch (modeId)` **直接吐 SVG 字符串**，没有 node/edge 对象、没有 id | 剧本想说「点亮 m1→s1 这条复制边」，**无从引用**。必须先抽出图元模型 |
| 5 | `src/lib/arch-motion.ts`（`svgMotionStyle()`：内嵌 CSS、尊重 `prefers-reduced-motion`、导出独立 .svg 也生效）现只被 `arch-canvas.ts` / `app/arch/diagrams.tsx` 消费 | 形态图一行没用。**现成的成熟方案可直接复用**，不必另造 |
| 6 | ⑤ 那一步现在是一屏卡片（`xl:grid-cols-2`）+ 迷你图 + 五根滑杆 + 容量摘要 | 页面已经不空。动画面板必须**默认收起**，否则把表单挤没 |
| 7 | `arch-canvas.ts` 已有 `opts.hooks` 双模式（交互态 / 导出态） | 播放器的「可交互」与「导出静态图」两条路，照抄这个设计 |

一句话：**代码骨架有现成的可抄，缺的是①图元模型 ②剧本数据 ③播放器组件。**

## 2. 五个设计决策（建议照此执行）

### D1. 剧本是数据，不是代码
跟「Rule as Data」同一条原则。每个形态的机理写成**结构化剧本**，三种出口共用一份：
- ① **页面动画**：播放器按步播放
- ② **导出 SVG**：渲染成 N 步并排静态图 + 旁白，带 `svgMotionStyle()` 的内嵌 CSS 流光（双击打开也活着）
- ③ **给 AI / 文档**：Markdown 文本（"Redis Cluster 读路径：CRC16(key)%16384 → 命中非本槽 → MOVED 重定向 → 重打到目标分片"）

### D2. 每个形态必须回答同样的三问，缺一个 build 就失败
用户原话就是这三问，直接钉成 schema 的**硬约束**：

| 场景 id | 回答什么 | Redis Cluster 的例子 |
|---|---|---|
| `read` | 数据怎么查 | CRC16 算槽 → 打错分片回 MOVED → 重定向 → 命中/未命中回源 |
| `write` | 数据怎么存 | 写主分片 → 主异步复制到从 → AOF 落盘策略 |
| `failover` | 容灾怎么做 | PFAIL → 多数主确认 FAIL → 从节点晋升 → 槽归属更新 → 客户端重定向 |

跟 C1-2「driver 必须被引用否则 build 失败」是同一款硬闸门——不靠人记。

### D3. 先重构出图元模型，再谈动画
`topologyModeSvg()` 改成两段：**先产图元（nodes[] + edges[]，带 id），再渲染**。
- 渲染函数签名不变 → `TopologyPicker` 迷你图、`buildTopologySvg` 卡片两处消费**零改动**（【17】的视觉断言也不会被震到）
- 剧本只引用 id，不碰坐标

### D4. 动画分两层，别混为一谈
| 层 | 手段 | 用途 |
|---|---|---|
| **常态流光** | 复用 `arch-motion.ts` 的 CSS（`.am-flow` / `.am-run`） | 复制流、心跳、轮询——一直在动的背景 |
| **分步剧情** | React state 控制 `stepIndex`，CSS `offset-path` 让 token 沿边跑 | 「第 3 步：主挂了」这种有因果的顺序 |

⚠️ token 不用 SMIL `<animateMotion>`（Chrome 曾标记移除，且 `arch-motion.ts` 开头已写明理由）→ 用 CSS `offset-path: path(...)`，降级到 `stroke-dashoffset` 光带。
⚠️ `prefers-reduced-motion: reduce` → 自动停在首帧，只留「下一步」手动按钮 + 全量文字，**绝不强制播放**。

### D5. 数字不许编造（沿用评分卡那条规矩）
16384 槽、CRC16、`cluster-node-timeout` 默认 15s、Gossip 每秒 PING——这些是**可溯源事实**，可以写。
延迟毫秒数、「提升 3 倍」这类**不许写**；只能写「量级」并标 `~`，或干脆只写关系不写数字。剧本每步的 `caption` 若出现数字，必须在 `refs` 里给出处。

## 3. 数据模型

### 3.1 新增事实源 `tools/content/stack_topology_flows.py`

```python
# -*- coding: utf-8 -*-
"""部署形态机理剧本：每个形态回答「怎么查 / 怎么存 / 挂了怎么办」。"""

TOPOLOGY_FLOWS = {
    "cache": {                      # 维度 id
        "redis": {                  # 选项 id —— 走 per-option 覆盖，不再 '*' 通配
            "cluster": {            # 形态 id，必须与 TOPOLOGY 里的 mode.id 对齐
                "nodes": [
                    {"id": "client", "label": "应用", "kind": "client"},
                    {"id": "m1", "label": "分片1 主", "kind": "primary", "slot": "0-5460"},
                    {"id": "m2", "label": "分片2 主", "kind": "primary", "slot": "5461-10922"},
                    {"id": "s1", "label": "分片1 从", "kind": "replica"},
                ],
                "edges": [
                    {"id": "c-m1", "from": "client", "to": "m1", "kind": "data"},
                    {"id": "c-m2", "from": "client", "to": "m2", "kind": "data"},
                    {"id": "m1-s1", "from": "m1", "to": "s1", "kind": "repl"},
                ],
                "scenes": [
                    {
                        "id": "read",
                        "title": "读：一个 key 怎么被找到",
                        "steps": [
                            {"caption": "客户端本地算 CRC16(key) % 16384，直接知道该去哪个分片",
                             "highlight": ["client"]},
                            {"caption": "槽不在自己身上 → 目标分片回 MOVED，带上正确的槽归属",
                             "active": ["c-m1"], "token": {"edge": "c-m1", "label": "GET"}},
                            {"caption": "按 MOVED 重打到分片 2 → 命中返回",
                             "highlight": ["m2"], "active": ["c-m2"], "token": {"edge": "c-m2", "label": "GET"}},
                        ],
                        "refs": ["Redis Cluster spec: 16384 hash slots / CRC16 / MOVED"],
                    },
                    {"id": "write",   "title": "写：数据怎么落下去", "steps": [...]},
                    {"id": "failover","title": "灾：主节点挂了会怎样", "steps": [...]},
                ],
            },
        },
    },
}
```

字段口径（写死，后端/前端/校验三处共用）：

| 字段 | 含义 | 约束 |
|---|---|---|
| `nodes[].id` | 图元 id，剧本引用它 | 同形态内唯一 |
| `nodes[].kind` | `client / primary / replica / proxy / store / cache` | 决定配色与**自动布局**（主在上、从在下、proxy 在左） |
| `nodes[].x/.y` | 显式坐标，可选 | 给了就用，不给按 kind 自动排 |
| `edges[].kind` | `data / repl / heartbeat / route` | 决定线型：实线=data，虚线=repl，点线=heartbeat |
| `scenes[].id` | **必须是 `read` / `write` / `failover` 三者齐全** | 缺一 → build 失败 |
| `steps[].caption` | 旁白，一句话说清这一步在发生什么 | ≤ 40 字 |
| `steps[].highlight` | 本步高亮的节点 | 必须存在于 `nodes` |
| `steps[].active` | 本点点亮的边 | 必须存在于 `edges` |
| `steps[].token` | 沿边跑的数据包 `{edge, label}` | `edge` 必须存在于 `edges` |
| `scenes[].refs` | 数字/事实的出处 | caption 含数字时必填 |

### 3.2 同时修掉 `*` 通配（D3 的附带收益）

`TOPOLOGY['cache']` 从 `{"*": {...}}` 拆成按选项：

| 选项 | 形态表 | 变化 |
|---|---|---|
| `caffeine` | single / multilevel | **删掉**主从、集群（修 bug） |
| `redis` | single / masterslave / **sentinel** / **cluster** / multilevel | **新增**哨兵、Cluster（用户点名要看的） |
| `none` | 无形态表 | 直接不出现 |

## 5. 验收标准

**每批都要过的四道：**

1. `python tools/build-content.py` → 0 错（含新增的剧本断言）
2. `node scripts/sync-content.mjs` → 干净
3. `npm run verify` 全绿，且**新增断言数同步进四处数字**（硬约定 9）
4. `node scripts/next-run.mjs build` → 0 错，然后真点一遍：⑤ 部署形态 → 缓存卡片 → ▷ 看机理 → 三个场景各自放一遍

**【22】层建议断言（首版 ~12 条）：**

| # | 断言 | 防什么 |
|---|---|---|
| 1 | 每个有剧本的形态，`scenes` 必须齐 `read`/`write`/`failover` | 场景漏写 |
| 2 | `steps[].highlight` / `active` / `token.edge` 引用的 id 必须存在 | 悬空引用（播放时静默不动，最难查） |
| 3 | flows 的 `(dim, opt, mode)` 必须在 `TOPOLOGY` 里存在 | 给不存在的形态写剧本 = 白写 |
| 4 | 剧本画的节点数 == 该形态 `replicas`（`client` 不计） | **动画画 3 个、K8s 写 2 个**——本项目最忌的这种事故 |
| 5 | `caption` 含数字时必须带 `refs` | 编数字 |
| 6 | `edges[].from/to` 必须存在 | 边悬空 |
| 7 | Caffeine 不得出现 `masterslave`/`cluster` 形态 | 回归 bug #2 |
| 8 | 播放器尊重 `prefers-reduced-motion`（源码断言） | 无障碍退化 |
| 9 | `topologyModeSvg()` 对 13 个既有 modeId 的输出与重构前**逐字符一致**（快照比对） | 重构震到【17】视觉断言 |
| 10 | 每个 `scene.steps.length >= 3` | 一步就演完 = 没讲清 |
| 11 | 类型 ↔ 事实源双向比（`content-types.ts` ↔ flows） | 加字段漏改类型 |
| 12 | 播放器默认**收起** | 把 ⑤ 的表单挤没 |

> 第 9 条是本批**最关键的护栏**：改渲染函数动的是全局几何，必须拿快照锁死「重构前后一模一样」，否则迷你图和形态图卡片会悄悄变形。

## 6. 风险

| 风险 | 应对 |
|---|---|
| **内容是主要工作量**（一个形态 3 场景 × 4-6 步，写准要查文档） | 分批；P0 只做 Redis。宁可少而准，不要多而糊 |
| 重构 `topologyModeSvg()` 会震到【17】【18】装配台断言 | 先出快照、重构后逐字符比对（断言 #9） |
| 改 `TOPOLOGY` 结构会影响 ⑥ 交付的副本数计算 | `replicas` 字段不动，只动 modes 集合；交付侧回归一遍 |
| `offset-path` 兼容性 | 老浏览器降级到 `stroke-dashoffset` 光带（现成 `.am-run`） |
| 动画抢戏，把选型表单挤没 | 默认收起 + 折叠面板；**不新增路由** |
| ⚠️ 多会话并发 | 动文件前取两次 md5；本计划不改任何代码，只加文档 |
