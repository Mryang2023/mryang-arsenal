# 前端 UI 模板可选化（Vue3 栈下多套 UI 模板）

## 目标

在 ⑤ 前端技术栈 步骤（/stack/env）里，选完 vue3-vite 后可以再选**一套 UI 模板**，选中的模板决定脚手架/导出 zip 里 frontend 包的实际内容。首批三套：

| 模板 id | 名称 | 内容 | 成本 |
|---|---|---|---|
| `element-admin`（默认） | Element Plus 经典侧边栏 | **现有模板原样迁入**，零改动 | 迁移 27 个文件位置 |
| `naive-admin` | Naive UI 管理端 | 同结构新写：n-layout/n-menu 布局、n-data-table CRUD、createDiscreteApi 消息、暗色友好 | 新写 ~25 个 .tpl |
| `element-topbar` | Element Plus 顶栏导航 | 复用 element-admin 的 api/stores/views/router，仅 layout/SideMenu→TopMenu/menu 装配不同 | 拷贝后改 ~8 个文件 |

react-vite 保持"规划中"灰显不动；`none` 语义不变。

## 数据模型与事实源

- 选择状态：`useStackChannel` 新增 `feUi`（默认 `'element-admin'`），与 feBase 同组持久化（`picks-store.ts` 的 ScaffoldDraft 加 `feUi` 字段 + 旧草稿兜底 `'element-admin'`）。
- 事实源：`tools/content/stack_frontend.py` 的 FRONTEND 增 `templates`（vue3-vite 基底下的清单：id/name/summary/default），走既有管道 build-content.py → stack.json → sync-content.mjs → generated/stack.json；`env-form.ts` 暴露 `frontendTemplates`。
- **模板目录嵌套**：`arsenal-scaffold/frontend/vue3-vite/{element-admin,naive-admin,element-topbar}/**`（现有 27 文件 git mv 进 element-admin/）。zip 输出路径不变（仍 `frontend/src/...`），compose/Dockerfile/nginx/README-all 无需改动。

## 代码改造（去硬编码）

1. `frontend-plan.ts`：`buildFrontendFiles` 加 `templateId` 参数，PREFIX = `frontend/${feBase}/${templateId}/`，from 文案带模板名；双变体（dynamic 路由）逻辑按同名文件约定对每套模板生效。
2. `artifacts.ts`：出前端包门槛仍 `feBase === 'vue3-vite'`，透传 feUi。
3. `useStackChannel.ts`：feUi state + 持久化 + 进 buildExportArtifacts；feLabel 摘要显示「Vue3 · 模板名」；切 feBase 时 feUi 回默认。
4. `FrontendStep.tsx`：feBase=vue3-vite 时在基底卡下方渲染模板卡区（同一卡片语言，数据来自事实源清单）；页脚固定文案改为随模板。
5. `ScaffoldDelivery.tsx`：前端下载卡标注模板名。
6. `.verify/scaffold-check.ts`【3】：import↔package.json 零悬空检查从硬编码 `frontend/vue3-vite/` 泛化为**扫描所有 `frontend/<base>/<template>/` 模板目录**（每套模板都必须自洽）；【6】双变体断言改在默认模板上跑。**不新增断言项数**（脚手架层声明 17 项保持），模板目录齐全性由【1】的磁盘↔bundle 一致性自动覆盖。

## 验证与交付

1. `npm run sync`（重跑 build-content + build-scaffold-templates）→ 生成物刷新。
2. `npm run verify:project`（含 scaffold-check 七段）+ `typecheck` + 全量 `npm run verify` 退出码 0，项数口径不变。
3. 浏览器走查：/stack/env 选三套模板各一次 → /stack/delivery 三张 zip 下载内容抽查（naive-ui 包里无 element-plus 残留、element-topbar 布局文件正确、双变体勾菜单模块时 dynamic 路由在）。
4. 分批提交：事实源+迁移 / 新模板 / 链路参数化 / UI 接线，每笔独立可回退。

## 明确不做

- 不解锁 react-vite（保持占位）；不动 33 维度体系与后端包；占位符白名单仍 6 键；compose/部署编排不改。
